# 16.7.1-Synonym-Overview

## 1. What is a Synonym?

A **Synonym** is used to give **another name to a table**.

Think of it like giving a **nickname** to a table.

For example, suppose the actual table name is:

```text
EMP
```

We can create another name:

```text
EMP_DETAILS
```

Then `EMP_DETAILS` becomes a Synonym for `EMP`.

```text id="f2z8qk"
EMP
 ↓
Synonym
 ↓
EMP_DETAILS
```

The definition given is:

> **Synonym is used to give another name to the table.** 

---

# 2. Why do we need a Synonym?

Suppose the original table name is:

```text
EMP
```

We want to refer to this table using another name.

Instead of repeatedly using:

```text
EMP
```

we can create a Synonym such as:

```text
EMP_DETAILS
```

So:

```text
Original table
     ↓
    EMP
     ↓
Synonym name
     ↓
EMP_DETAILS
```

The Synonym provides another name for the table.

---

# 3. Simple Real-Life Example

Imagine a person's official name is:

```text
Mohammed Abdul
```

But everyone calls him:

```text
Abdul
```

Both names refer to the same person.

Similarly:

```text
Actual table → EMP
Synonym      → EMP_DETAILS
```

Both refer to the same table.

---

# 4. Basic Structure

```text id="d0kqcg"
             EMP
              ↑
              │
          Synonym
              │
              ↓
         EMP_DETAILS
```

The important point is:

> **The Synonym is another name for the existing table.**

---

# 5. Creating a Synonym

The command used to create a Synonym is:

```text id="4b6d0x"
CREATE SYNONYM
```

### Question:

What is the syntax for creating a Synonym?

### Answer / Syntax:

```sql id="7xj3ab"
CREATE SYNONYM synonym_name
FOR table_name;
```

The creation syntax is given as `create synonym synonym_name for table_name;`. 

---

# 6. Example

Suppose the existing table is `EMP`.

### Question:

Create a Synonym named `emp_details` for the `emp` table.

### Answer / Query:

```sql id="o3x3f4"
CREATE SYNONYM emp_details
FOR emp;
```

### Explanation

Here:

| Part             | Meaning                                       |
| ---------------- | --------------------------------------------- |
| `CREATE SYNONYM` | Creates a Synonym                             |
| `emp_details`    | New/alternate name                            |
| `FOR`            | Connects the Synonym with the existing object |
| `emp`            | Existing table                                |

So:

```text id="z4c8yp"
emp
 ↓
emp_details
```

`emp_details` is the Synonym name for `emp`.

The example `create synonym emp_details for emp;` is the given Synonym example.

# 8. Synonym Does Not Create a New Table

This is an important point.

Suppose:

```text id="m4o5kv"
EMP
```

is the original table.

After creating:

```text id="e0kq3d"
CREATE SYNONYM emp_details FOR emp;
```

we have:

```text id="y3d4k8"
EMP          ← Actual table
  ↑
  │
EMP_DETAILS  ← Synonym
```

The Synonym is **another name**, not another copy of the table.

# 10. Synonym vs Table

| Table                                  | Synonym                                      |
| -------------------------------------- | -------------------------------------------- |
| Actual database object containing data | Another name for an existing object          |
| Stores table data                      | Does not create a separate copy of the table |
| Example: `EMP`                         | Example: `EMP_DETAILS`                       |

### Remember:

```text
TABLE    → Actual object
SYNONYM  → Another name
```

---

# 11. Why is the Name "Synonym"?

The word **synonym** means a different word with the same meaning.

For example:

```text
Big ↔ Large
```

Similarly:

```text
EMP ↔ EMP_DETAILS
```

They are different names referring to the same table.

---

# 12. Important Points

* A Synonym gives **another name to a table**.
* `CREATE SYNONYM` is used to create it.
* General syntax:

```sql id="4p4dvs"
CREATE SYNONYM synonym_name
FOR table_name;
```

* Example:

```sql id="u2g1s7"
CREATE SYNONYM emp_details
FOR emp;
```

* `emp` is the existing table.
* `emp_details` is the Synonym.
* A Synonym is not a separate copy of the table.
