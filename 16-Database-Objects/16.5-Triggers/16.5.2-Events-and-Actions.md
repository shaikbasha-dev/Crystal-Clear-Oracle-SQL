# 16.5.2-Events-and-Actions

## 1. What is an Event?

An **event** is something that happens to a table and causes the Trigger to respond.

The three events used here are:

```text
INSERT
UPDATE
DELETE
```

A Trigger can be configured to execute either **BEFORE** or **AFTER** these events. 

---

## 2. What is an Action?

An **action** is the SQL operation that the Trigger performs when the specified event occurs.

So the basic idea is:

```text
EVENT
  ↓
Something happens to the table
  ↓
TRIGGER responds
  ↓
ACTION
  ↓
SQL statement executes
```

The two main components of a Trigger are **Event** and **Action**. 

---

# 3. Six Events and Actions

There are six combinations:

| No. | Timing | Event  |
| --: | ------ | ------ |
|   1 | BEFORE | INSERT |
|   2 | AFTER  | INSERT |
|   3 | BEFORE | UPDATE |
|   4 | AFTER  | UPDATE |
|   5 | BEFORE | DELETE |
|   6 | AFTER  | DELETE |



### Easy way to remember

```text
INSERT → BEFORE / AFTER
UPDATE → BEFORE / AFTER
DELETE → BEFORE / AFTER
```

---

# 4. BEFORE INSERT

### What does it mean?

The Trigger's action occurs **before a new row is inserted**.

```text
BEFORE INSERT
      ↓
Trigger Action
      ↓
INSERT
```

### Example situation

```text
A new employee is going to be inserted
              ↓
       BEFORE INSERT
              ↓
      Trigger performs action
              ↓
       Employee is inserted
```

---

# 5. AFTER INSERT

### What does it mean?

The Trigger's action occurs **after a new row has been inserted**.

```text
INSERT
  ↓
AFTER INSERT
  ↓
Trigger Action
```

---

# 6. BEFORE UPDATE

### What does it mean?

The Trigger's action occurs **before an existing row is updated**.

```text
BEFORE UPDATE
      ↓
Trigger Action
      ↓
UPDATE
```

---

# 7. AFTER UPDATE

### What does it mean?

The Trigger's action occurs **after an existing row has been updated**.

```text
UPDATE
  ↓
AFTER UPDATE
  ↓
Trigger Action
```

---

# 8. BEFORE DELETE

### What does it mean?

The Trigger's action occurs **before an existing row is deleted**.

```text
BEFORE DELETE
      ↓
Trigger Action
      ↓
DELETE
```

---

# 9. AFTER DELETE

### What does it mean?

The Trigger's action occurs **after an existing row has been deleted**.

```text
DELETE
  ↓
AFTER DELETE
  ↓
Trigger Action
```

---

# 10. Complete Picture

```text
                         TRIGGER
                            │
                 ┌──────────┴──────────┐
                 │                     │
               EVENT                 ACTION
                 │                     │
        ┌────────┼────────┐       SQL Statement
        │        │        │
      INSERT   UPDATE   DELETE
        │        │        │
      ┌─┴─┐    ┌─┴─┐    ┌─┴─┐
      │   │    │   │    │   │
    BEFORE AFTER BEFORE AFTER BEFORE AFTER
```

This gives the six combinations listed above. 

---

# 11. `:NEW` and `:OLD`

The Trigger section also associates row values with the events:

| Event  | Available reference |
| ------ | ------------------- |
| INSERT | `:NEW`              |
| UPDATE | `:NEW` and `:OLD`   |
| DELETE | `:OLD`              |



### Simple understanding

```text
INSERT
  ↓
New row
  ↓
:NEW
```

```text
UPDATE
  ↓
Old value → New value
  ↓
:OLD     → :NEW
```

```text
DELETE
  ↓
Existing row is removed
  ↓
:OLD
```

---

# 12. Example Showing Event + Action

### Question:

Create a Trigger that performs an action before an insert occurs on `table1`.

### Answer / Query:

```sql
CREATE TRIGGER dec
BEFORE INSERT
ON table1
FOR EACH ROW
BEGIN
    INSERT INTO table2 VALUES(:NEW.id, :NEW.name);
END;
```



### What is the Event?

```text
BEFORE INSERT
```

### What is the Action?

```sql
INSERT INTO table2 VALUES(:NEW.id, :NEW.name);
```

### What is `:NEW`?

It represents the new values associated with the inserted row. 

---

# 13. Event vs Action

| Event                      | Action                                       |
| -------------------------- | -------------------------------------------- |
| Something that happens     | What the Trigger performs                    |
| INSERT                     | SQL operation executed in response           |
| UPDATE                     | SQL operation executed in response           |
| DELETE                     | SQL operation executed in response           |
| Can happen BEFORE or AFTER | Executes according to the Trigger definition |

### Easy memory trick:

> **Event = What happened?**
> **Action = What should the Trigger do?**

# 14. Interview Questions

### Q1. What are the two main components of a Trigger?

**Answer:**

```text
1. Event
2. Action
```

### Q2. What are the three main events?

**Answer:**

```text
INSERT
UPDATE
DELETE
```

### Q3. How many event/timing combinations are there?

**Answer:**

```text
6
```

They are:

```text
Before Insert
After Insert
Before Update
After Update
Before Delete
After Delete
```

### Q4. What is the difference between BEFORE and AFTER?

**Answer:**

```text
BEFORE → Trigger action occurs before the event

AFTER  → Trigger action occurs after the event
```

### Q5. Which reference is used with INSERT?

**Answer:** `:NEW`

### Q6. Which references are used with UPDATE?

**Answer:** `:OLD` and `:NEW`

### Q7. Which reference is used with DELETE?

**Answer:** `:OLD`
