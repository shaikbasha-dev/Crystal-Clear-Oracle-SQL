# 16.5.11-New-and-Old

## 1. What are `:NEW` and `:OLD`?

In a Trigger, `:NEW` and `:OLD` are used to refer to the values of a row involved in an `INSERT`, `UPDATE`, or `DELETE` event.

The basic mapping is:

```text
INSERT → :NEW
UPDATE → :NEW + :OLD
DELETE → :OLD
```

---

## 2. Why do we need `:NEW` and `:OLD`?

A Trigger may need to know the values of the row involved in the event.

For example:

```text
INSERT
   ↓
A new row is coming
   ↓
:NEW
```

For UPDATE:

```text
Old value
   ↓
:OLD

New value
   ↓
:NEW
```

For DELETE:

```text
Existing row
   ↓
:OLD
   ↓
DELETE
```

The Trigger section gives these exact associations. 

---

# 3. `:NEW`

`:NEW` represents the **new row value** involved in the operation.

It is associated with:

```text
INSERT
UPDATE
```

According to the mapping:

```text
INSERT → :NEW
UPDATE → :NEW
```

---

## 4. `:NEW` with INSERT

When a new row is inserted, the row is a **new row**.

### Question:

Which Trigger reference is used for an INSERT event?

### Answer:

```text
:NEW
```

### Example:

Suppose we insert:

### Question:

Insert a new employee with ID `101` and name `Basha`.

### Answer / Query:

```sql
INSERT INTO emp VALUES(101, 'Basha');
```

The newly inserted values can be referred to as:

```text
:NEW.id   → 101
:NEW.name → Basha
```

So:

```text
INSERT
  ↓
:NEW
```

---

# 5. `:NEW` with UPDATE

UPDATE has both an old value and a new value.

### Question:

Which Trigger references are used with an UPDATE event?

### Answer:

```text
:OLD
:NEW
```

For example:

```text
Before UPDATE:
Salary = 20,000
     ↓
:OLD.salary

After UPDATE:
Salary = 25,000
     ↓
:NEW.salary
```

So:

```text
:OLD → previous value
:NEW → new value
```

---

# 6. `:OLD`

`:OLD` represents the **existing/previous value** involved in the operation.

It is associated with:

```text
UPDATE
DELETE
```

The mapping is:

```text
UPDATE → :OLD
DELETE → :OLD
```

---

# 7. `:OLD` with UPDATE

### Question:

What does `:OLD` represent during an UPDATE?

### Answer:

It represents the value **before the UPDATE**.

Example:

```text
Before UPDATE:

Salary = 20,000
     ↓
:OLD.salary
```

If the salary changes to `25,000`:

```text
:OLD.salary = 20,000
:NEW.salary = 25,000
```

---

# 8. `:OLD` with DELETE

When a row is deleted, it already exists before deletion.

### Question:

Which Trigger reference is used with a DELETE event?

### Answer:

```text
:OLD
```

Example:

```text
Before DELETE:

ID       = 101
Name     = Basha
Salary   = 25000
```

These existing values can be referred to as:

```text
:OLD.id
:OLD.name
:OLD.salary
```

Then the row is deleted.

```text
:OLD
  ↓
DELETE
```

---

# 9. Complete Mapping

| Event  | `:NEW` | `:OLD` |
| ------ | :----: | :----: |
| INSERT |    ✅   |    ❌   |
| UPDATE |    ✅   |    ✅   |
| DELETE |    ❌   |    ✅   |

This gives the simple rule:

```text
INSERT → :NEW
UPDATE → :OLD + :NEW
DELETE → :OLD
```



---

# 10. Easy Real-Life Example

Imagine changing someone's salary.

Before:

```text
Salary = ₹20,000
```

After:

```text
Salary = ₹25,000
```

A Trigger can conceptually see:

```text
:OLD.salary = ₹20,000
:NEW.salary = ₹25,000
```

Therefore:

```text
:OLD → What was there before?
:NEW → What is the new value?
```

---

# 11. Relation with the Six Trigger Types

| Trigger       | Reference      |
| ------------- | -------------- |
| BEFORE INSERT | `:NEW`         |
| AFTER INSERT  | `:NEW`         |
| BEFORE UPDATE | `:OLD`, `:NEW` |
| AFTER UPDATE  | `:OLD`, `:NEW` |
| BEFORE DELETE | `:OLD`         |
| AFTER DELETE  | `:OLD`         |

The timing (`BEFORE`/`AFTER`) does not change the basic `:OLD`/`:NEW` mapping; the event determines which references are associated.

---

# 12. Example with Trigger

### Question:

Create a BEFORE INSERT Trigger that uses the newly inserted `id` and `name`.

### Answer / Query:

```sql
CREATE TRIGGER dec
BEFORE INSERT
ON table1
FOR EACH ROW
BEGIN
    INSERT INTO table2 VALUES(:NEW.id, :NEW.name);
END;
```

Here:

```text
INSERT event
     ↓
:NEW.id
:NEW.name
```

The Trigger example uses `:NEW.id` and `:NEW.name`. 

---

# 13. `:NEW` vs `:OLD`

| `:NEW`           | `:OLD`                  |
| ---------------- | ----------------------- |
| New value        | Previous/existing value |
| Used with INSERT | Used with DELETE        |
| Used with UPDATE | Used with UPDATE        |
| INSERT → `:NEW`  | DELETE → `:OLD`         |
| UPDATE → `:NEW`  | UPDATE → `:OLD`         |

### Easy memory:

```text
NEW → New
OLD → Previous
```

---

# 14. Most Important Interview Questions

### Q1. What is `:NEW`?

**Answer:**
`:NEW` is used to refer to the new row values associated with INSERT and UPDATE events.

### Q2. What is `:OLD`?

**Answer:**
`:OLD` is used to refer to the previous/existing row values associated with UPDATE and DELETE events.

### Q3. Which reference is used with INSERT?

**Answer:**

```text
:NEW
```

### Q4. Which references are used with UPDATE?

**Answer:**

```text
:OLD
:NEW
```

### Q5. Which reference is used with DELETE?

**Answer:**

```text
:OLD
```

### Q6. Can `:OLD` be used with INSERT?

**Answer:**
No. INSERT deals with a new row, so the relevant reference is `:NEW`.

### Q7. Can `:NEW` be used with DELETE?

**Answer:**
No. DELETE deals with an existing row being removed, so the relevant reference is `:OLD`.

# 15. Quick Revision

```text
                 TRIGGER
                    │
          ┌─────────┼─────────┐
          ↓         ↓         ↓
       INSERT     UPDATE    DELETE
          ↓         ↓         ↓
        :NEW    :OLD + :NEW  :OLD
```

### Golden Rule

> **INSERT → NEW**
> **UPDATE → OLD + NEW**
> **DELETE → OLD**

This is the easiest way to remember `:NEW` and `:OLD`.
