# 16.2.1-Views-Overview

## 1. What is a View?

A **View** is a **virtual table** created on the basis of an original/actual table.

Think of it like this:

```text
Actual Table
     ↓
   Query
     ↓
    View
     ↓
Virtual Table
```

A View gives us a table-like way of looking at selected data from an actual table. 

---

## 2. Why do we use Views?

There are two important purposes:

### 1. To make complex queries simple

Suppose a query is complicated and we need its result again and again.

Instead of writing the complete query every time, we can create a View.

```text
Complex Query
      ↓
     View
      ↓
Simple SELECT
```

### 2. To provide Data Independence

Views provide **data independence**.

This means the user can work with the required data through the View without directly dealing with the complete underlying table structure.



---

# 3. Simple Example

Suppose the `emp` table contains:

```text
EMP
------------------------------------------------
emp_id | f_name | salary | dept_id | ...
```

But we need only:

```text
f_name
salary
dept_id
```

and only employees whose:

```text
dept_id = 22
```

We can create a View for this requirement.

```text
EMP TABLE
   │
   │  SELECT f_name, salary, dept_id
   │  WHERE dept_id = 22
   ↓
VIEW: DEC
   │
   ↓
Virtual Table
```

---

# 4. Main Operations on a View

The three operations covered are:

```text
VIEW
 │
 ├── Create View
 │
 ├── Fetch Data from View
 │
 └── Delete View
```

# 5. Creating a View

### Question:

How do you create a View?

### Syntax:

```sql
CREATE VIEW view_name
AS
SQL Query;
```



### Meaning

| Part          | Meaning                                       |
| ------------- | --------------------------------------------- |
| `CREATE VIEW` | Creates a View                                |
| `view_name`   | Name of the View                              |
| `AS`          | Connects the View with the query              |
| `SQL Query`   | Query whose result is represented by the View |

---

# 6. Example of Creating a View

### Question:

Create a View named `dec` that displays `f_name`, `salary`, and `dept_id` from `emp` for employees whose department ID is 22.

### Query:

```sql
CREATE VIEW dec
AS
SELECT f_name, salary, dept_id
FROM emp
WHERE dept_id = 22;
```



### Query Explanation

Let's understand it line by line:

```sql
CREATE VIEW dec
```

Creates a View with the name `dec`.

```sql
SELECT f_name, salary, dept_id
```

Selects three columns:

* `f_name`
* `salary`
* `dept_id`

```sql
FROM emp
```

The data comes from the `emp` table.

```sql
WHERE dept_id = 22;
```

Only employees belonging to department `22` are selected.

### Final idea

```text
EMP
 ↓
Filter dept_id = 22
 ↓
Select f_name, salary, dept_id
 ↓
VIEW: DEC
```

---

# 7. What does "Virtual Table" mean?

A View behaves like a table when we query it, but it is called a **virtual table**.

For example:

```text
Actual Table
    emp
      ↓
    Query
      ↓
Virtual Table
     dec
```

So we can use the View to retrieve the required result.

# 8. Important Points for Interview

### Q1. What is a View?

**Answer:**
A View is a virtual table created on the basis of an original/actual table.

### Q2. Why are Views used?

**Answer:**
Views are used to make complex queries simple and to provide data independence.

### Q3. Is a View an actual table?

**Answer:**
A View is a **virtual table**, not an independent physical table like the original table.

### Q4. What is the basic syntax for creating a View?

**Answer:**

```sql
CREATE VIEW view_name
AS
SQL Query;
```

# 9. Easy Memory Trick

Remember **VIEW** as:

> **V → Virtual table**
> **I → Improves simplicity of complex queries**
> **E → Easier data access**
> **W → Works based on an actual table**

### One-line interview answer:

> **A View is a virtual table created from an original table, mainly used to simplify complex queries and provide data independence.**
