# 19.1-Normalisation-Overview

## 1. What is Normalisation?

**Normalization** is a database design technique used to **organize data properly into tables**.

The main idea is:

> **Store each piece of information in the right place and reduce unnecessary repetition of data.**

Imagine we have this table:

| Student_ID | Student_Name | Course | Professor |
| ---------: | ------------ | ------ | --------- |
|        101 | Basha        | Java   | Kumar     |
|        102 | Ahmed        | Java   | Kumar     |
|        103 | Ravi         | Python | Ramesh    |
|        104 | Sana         | Java   | Kumar     |

Here, `Java` and `Kumar` are repeated several times.

Normalization helps us organize this information into separate related tables.

---

# 2. Why do we need Normalisation?

Suppose we keep everything in one large table.

```text id="e7e4b4"
Student + Course + Professor + Department + ...
                    ↓
             One huge table
                    ↓
          Data gets repeated
                    ↓
             Problems occur
```

Normalization helps us avoid unnecessary duplication and makes the database easier to maintain.

---

# 3. Simple Real-Life Example

Imagine you maintain student information in a notebook.

You write:

```text id="u4xk9d"
Basha → Java → Kumar
Ahmed → Java → Kumar
Ravi  → Python → Ramesh
Sana  → Java → Kumar
```

Notice:

```text id="9tqf7r"
Java → Kumar
Java → Kumar
Java → Kumar
```

The same information is being written again and again.

Instead, we can separate it:

### Student

| Student_ID | Student_Name |
| ---------: | ------------ |
|        101 | Basha        |
|        102 | Ahmed        |
|        103 | Ravi         |
|        104 | Sana         |

### Course

| Course_ID | Course | Professor |
| --------: | ------ | --------- |
|         1 | Java   | Kumar     |
|         2 | Python | Ramesh    |

### Enrollment

| Student_ID | Course_ID |
| ---------: | --------: |
|        101 |         1 |
|        102 |         1 |
|        103 |         2 |
|        104 |         1 |

Now information is stored more systematically.

---

# 4. What Problem Does Normalisation Solve?

A poorly designed table can cause three important problems called **anomalies**:

```text id="2n5wq7"
              Database Problems
                     │
          ┌──────────┼──────────┐
          ↓          ↓          ↓
       INSERT      UPDATE      DELETE
       Anomaly     Anomaly     Anomaly
```

These are called:

1. **Insert Anomaly**
2. **Update Anomaly**
3. **Delete Anomaly**

We will study these separately in the next section.

---

# 5. Main Goal of Normalisation

The main goals are:

```text id="g9i7ba"
Normalisation
     │
     ├── Reduce unnecessary data repetition
     │
     ├── Organize data properly
     │
     ├── Reduce data anomalies
     │
     └── Improve database design
```

The important thing is **not simply splitting tables randomly**.

We split tables according to the relationships between the data.

---

# 6. Normal Forms

Normalization is performed through different **Normal Forms**.

The important sequence is:

```text id="l3q9sa"
UNF
 ↓
1NF
 ↓
2NF
 ↓
3NF
 ↓
BCNF
 ↓
4NF
 ↓
5NF
```

### What does this mean?

Each normal form imposes additional rules on how data should be organized.

Think of it like cleaning a room:

```text id="5q9h3j"
Messy Room
    ↓
Basic Cleaning
    ↓
Better Organization
    ↓
More Organization
    ↓
Highly Organized
```

Similarly:

```text id="w3t2rf"
UNF → 1NF → 2NF → 3NF → BCNF → 4NF → 5NF
```

# 8. What Happens in Each Normal Form?

Don't memorize these yet. We will study each one separately.

For now, remember the basic idea:

| Normal Form | Main idea                                    |
| ----------- | -------------------------------------------- |
| **1NF**     | Remove repeating groups / make values atomic |
| **2NF**     | Remove partial dependency                    |
| **3NF**     | Remove transitive dependency                 |
| **BCNF**    | Stronger version of 3NF                      |
| **4NF**     | Deals with multivalued dependencies          |
| **5NF**     | Deals with join dependencies                 |

The detailed rules and examples will come in their respective folders.

---

# 9. Normalisation Does Not Mean "More Tables = Better"

This is an important point.

Suppose we have:

```text id="g4p1x2"
Student
```

We should not create ten tables simply because we can.

The purpose is to create a **logical and well-structured database**.

For example:

```text id="b8j3fd"
Student
   ↓
Course
   ↓
Professor
```

The tables should have meaningful relationships.

---

# 10. Normalisation and Oracle SQL

Normalization is a **database design concept**, not something unique to Oracle.

Oracle SQL provides the commands and features used to implement the design.

For example, after normalization, tables may be connected using:

```text id="w2v8k5"
PRIMARY KEY
     ↓
FOREIGN KEY
     ↓
JOIN
```

Example:

```text id="x1k7p3"
STUDENT
────────────
Student_ID  ← Primary Key
Student_Name
Course_ID   ← Foreign Key
```

and:

```text id="v5m2za"
COURSE
────────────
Course_ID   ← Primary Key
Course_Name
```

The relationship between the tables can then be used in SQL queries.

---

# 11. Normalisation vs Just Removing Duplicate Rows

These are **not the same thing**.

Suppose:

|  ID | Name  | Course |
| --: | ----- | ------ |
| 101 | Basha | Java   |
| 102 | Ahmed | Java   |

There are no completely duplicate rows.

But:

```text
Java
Java
```

is still repeated information.

Normalization looks at the **structure and dependencies of the data**, not merely whether entire rows are duplicates.

# 13. One Simple Example of the Need

Suppose we have:

| Student_ID | Student_Name | Course_ID | Course_Name |
| ---------: | ------------ | --------: | ----------- |
|        101 | Basha        |       C01 | Java        |
|        102 | Ahmed        |       C01 | Java        |
|        103 | Ravi         |       C02 | Python      |

The information:

```text
C01 → Java
```

is repeated.

If the name of the course changes from:

```text
Java
```

to:

```text
Advanced Java
```

we may need to update multiple rows.

This is an example of the kind of problem that normalization helps us design against.

# 16. Interview Questions

### Q1. What is Normalisation?

**Answer:**

> Normalization is a database design technique used to organize data into properly structured tables, reduce redundancy, and avoid data anomalies.

### Q2. Why is Normalisation required?

**Answer:**

> Normalization is used to reduce unnecessary data repetition and minimize insert, update, and delete anomalies.

### Q3. What are Normal Forms?

**Answer:**

> Normal Forms are stages/rules used to organize a database progressively.

```text
1NF → 2NF → 3NF → BCNF → 4NF → 5NF
```

### Q4. What are the three common database anomalies?

**Answer:**

```text
Insert Anomaly
Update Anomaly
Delete Anomaly
```

### Q5. Is Normalisation specific to Oracle?

**Answer:**

> No. Normalization is a relational database design concept. It can be implemented using Oracle and other relational database systems.
