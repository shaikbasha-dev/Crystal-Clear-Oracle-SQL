# 16.5.9-Creating-a-Trigger

## 1. What does Creating a Trigger mean?

Creating a Trigger means **creating a prepared SQL statement, saving it in the database, and associating it with a particular event**.

When that event occurs, the Trigger executes its defined action automatically.

```text id="8x2q6m"
CREATE TRIGGER
      ↓
Trigger is saved in database
      ↓
Specified event occurs
      ↓
Trigger executes automatically
```

A Trigger has two main components:

```text id="4h7w2p"
EVENT  → What happens?
ACTION → What should the Trigger do?
```

---

# 2. General Syntax

### Question:

What is the syntax for creating a Trigger?

### Answer / Syntax:

```sql id="p3y8k1"
CREATE TRIGGER trigger_name
[BEFORE AFTER] [INSERT UPDATE DELETE]
ON table_name
FOR EACH ROW
BEGIN
    SQL Query;
END;
```

This is the general Trigger-creation syntax. 

---

# 3. Understanding the Syntax

| Syntax                         | Meaning                                  |
| ------------------------------ | ---------------------------------------- |
| `CREATE TRIGGER`               | Creates a Trigger                        |
| `trigger_name`                 | Name given to the Trigger                |
| `BEFORE` / `AFTER`             | Specifies when the Trigger action occurs |
| `INSERT` / `UPDATE` / `DELETE` | Specifies the event                      |
| `ON table_name`                | Specifies the table                      |
| `FOR EACH ROW`                 | Trigger applies to each affected row     |
| `BEGIN`                        | Starts the Trigger body                  |
| `SQL Query`                    | Action performed by the Trigger          |
| `END`                          | Ends the Trigger                         |

---

# 4. How to Create a Trigger — Step by Step

There are four important things to decide:

```text id="0n9b5m"
1. Trigger Name
       ↓
2. BEFORE or AFTER
       ↓
3. INSERT / UPDATE / DELETE
       ↓
4. SQL Action
```

For example:

```text id="f0t4qs"
Trigger Name → dec
Timing       → BEFORE
Event        → INSERT
Table        → table1
Action       → INSERT into table2
```

---

# 5. Example of Creating a Trigger

### Question:

Create a Trigger named `dec` that executes **before INSERT** on `table1` and inserts the new `id` and `name` into `table2`.

### Answer / Query:

```sql id="b5v2c8"
CREATE TRIGGER dec
BEFORE INSERT
ON table1
FOR EACH ROW
BEGIN
    INSERT INTO table2 VALUES(:NEW.id, :NEW.name);
END;
```

The example uses `:NEW.id` and `:NEW.name` for the values of the newly inserted row. 

> **Correction:** The original example has `before inser`; the correct keyword is `BEFORE INSERT`.

---

# 6. Understanding This Trigger

Let's separate it:

### Trigger name

```sql id="f7q1ra"
dec
```

This is simply the name of the Trigger.

### Timing

```sql id="l7k2pm"
BEFORE
```

The Trigger action executes before the event.

### Event

```sql id="5g3t8x"
INSERT
```

The Trigger is activated because an INSERT event occurs.

### Table

```sql id="w2n6qd"
ON table1
```

The Trigger is associated with `table1`.

### Row-level execution

```sql id="6f4m1p"
FOR EACH ROW
```

The Trigger is defined for each affected row.

### Action

```sql id="9y3k5v"
INSERT INTO table2 VALUES(:NEW.id, :NEW.name);
```

This is the SQL operation performed by the Trigger.

---

# 7. Complete Execution Flow

Suppose we execute:

### Question:

Insert a new row into `table1`.

### Answer / Query:

```sql id="m8q4s2"
INSERT INTO table1 VALUES(1, 'A');
```

The Trigger responds automatically:

```text id="7x4c9n"
INSERT into table1
       ↓
BEFORE INSERT Trigger
       ↓
:NEW.id   = 1
:NEW.name = A
       ↓
INSERT into table2
```

The Trigger action is:

```sql id="r6t2w9"
INSERT INTO table2 VALUES(:NEW.id, :NEW.name);
```

So the new values from `table1` are used in the Trigger action.

---

# 8. Why Do We Use `:NEW`?

For an INSERT event, the row is **new**.

Therefore:

```text id="x1q7m3"
INSERT
  ↓
:NEW
```

The row-reference rules are:

| Event  | Reference       |
| ------ | --------------- |
| INSERT | `:NEW`          |
| UPDATE | `:OLD` + `:NEW` |
| DELETE | `:OLD`          |

# 10. Creating vs Calling a Trigger

A major difference from a Stored Procedure is that a Trigger is **not normally called by writing its name in a separate call block**.

### Stored Procedure

```text id="8y3k5r"
CREATE PROCEDURE
       ↓
Stored
       ↓
Explicitly CALL
       ↓
Execute
```

### Trigger

```text id="0m7x4q"
CREATE TRIGGER
       ↓
Stored
       ↓
Specified event occurs
       ↓
Automatically executes
```

Triggers are described as being called autonomously. 

---

# 11. Important Points

* `CREATE TRIGGER` is used to create a Trigger.
* A Trigger is saved in the database.
* `BEFORE` or `AFTER` specifies timing.
* `INSERT`, `UPDATE`, or `DELETE` specifies the event.
* `ON table_name` specifies the table.
* `FOR EACH ROW` is part of the creation syntax.
* The SQL statement inside `BEGIN ... END` is the Trigger action.
* INSERT uses `:NEW`.
* UPDATE uses `:OLD` and `:NEW`.
* DELETE uses `:OLD`.
