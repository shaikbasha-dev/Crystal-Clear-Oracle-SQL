# 19.8-Fourth-Normal-Form-4NF

## 1. What is 4NF?

**4NF (Fourth Normal Form)** is the fourth level of database normalization.

4NF deals mainly with **Multivalued Dependencies (MVDs)**.

### Simple definition

> **A table is in 4NF when it is in BCNF and does not contain any non-trivial multivalued dependency unless the determinant is a super key.**

For beginner understanding:

> **4NF removes unwanted independent multi-valued relationships from the same table.**

---

# 2. First Understand the Problem

Suppose a student can have:

* multiple **skills**
* multiple **hobbies**

And the skills and hobbies are **independent** of each other.

Consider:

| Student | Skill  | Hobby   |
| ------- | ------ | ------- |
| Ravi    | Java   | Cricket |
| Ravi    | Java   | Music   |
| Ravi    | Python | Cricket |
| Ravi    | Python | Music   |

Why do we have four rows?

Because Ravi has:

```text
Skills:
Java
Python
```

and independently:

```text
Hobbies:
Cricket
Music
```

Every skill is being combined with every hobby.

This creates unnecessary combinations.

---

# 3. What is a Multivalued Dependency?

A **Multivalued Dependency (MVD)** occurs when one attribute determines **multiple independent values** of another attribute.

It is represented using:

```text id="3u9x6r"
A →→ B
```

The symbol:

```text
→→
```

means **"multivalued dependency."**

### Example

If Ravi can have multiple skills independently of his hobbies:

```text id="8n5y4v"
Student →→ Skill
```

Similarly:

```text id="p8l1xq"
Student →→ Hobby
```

This means:

> A student can have multiple skills and multiple hobbies independently.

---

# 4. Functional Dependency vs Multivalued Dependency

This distinction is important.

### Functional Dependency

```text id="m6k9yw"
A → B
```

means:

> One value of A determines one value of B.

Example:

```text id="a2f5cx"
Student_ID → Student_Name
```

---

### Multivalued Dependency

```text id="r3h7pz"
A →→ B
```

means:

> One value of A can determine multiple values of B independently.

Example:

```text id="v5d8qa"
Student →→ Skill
```

### Easy memory

```text id="1v4n7x"
→   = Functional Dependency
→→  = Multivalued Dependency
```

---

# 5. Why is This a Problem?

Consider:

| Student | Skill  | Hobby   |
| ------- | ------ | ------- |
| Ravi    | Java   | Cricket |
| Ravi    | Java   | Music   |
| Ravi    | Python | Cricket |
| Ravi    | Python | Music   |

Suppose Ravi learns another skill:

```text SQL
```

We may need to add:

| Student | Skill | Hobby   |
| ------- | ----- | ------- |
| Ravi    | SQL   | Cricket |
| Ravi    | SQL   | Music   |

Now the number of rows increases because every skill is combined with every hobby.

This creates unnecessary data repetition.

---

# 6. How 4NF Solves the Problem

Instead of storing both independent multi-valued relationships in one table, separate them.

### STUDENT_SKILL

| Student | Skill  |
| ------- | ------ |
| Ravi    | Java   |
| Ravi    | Python |

### STUDENT_HOBBY

| Student | Hobby   |
| ------- | ------- |
| Ravi    | Cricket |
| Ravi    | Music   |

Now the independent relationships are stored separately.

There is no need to generate combinations such as:

```text
Java + Cricket
Java + Music
Python + Cricket
Python + Music
```

---

# 7. Understanding the 4NF Rule

The formal rule is:

> A relation is in **4NF** if, for every non-trivial multivalued dependency `X →→ Y`, `X` is a super key.

### Formula

```text id="q3g7vs"
4NF
=
BCNF
+
No non-trivial MVD
where determinant is not a Super Key
```

Or more simply:

```text id="b7h2xm"
4NF → Remove problematic Multivalued Dependencies
```

---

# 8. Example of a 4NF Violation

Consider:

| Student | Skill  | Hobby   |
| ------- | ------ | ------- |
| Ravi    | Java   | Cricket |
| Ravi    | Java   | Music   |
| Ravi    | Python | Cricket |
| Ravi    | Python | Music   |

Suppose:

```text id="r5p3xa"
Student →→ Skill
```

and:

```text id="q8w1lc"
Student →→ Hobby
```

Here `Student` determines multiple skills and multiple hobbies independently.

But:

```text id="u2c7nf"
Student
```

does not uniquely identify a row in this table.

Therefore, the multivalued dependency creates a 4NF problem.

---

# 9. Decomposition into 4NF

### Before

```text id="6j8s0p"
STUDENT_SKILL_HOBBY
        │
        ├── Student
        ├── Skill
        └── Hobby
```

The two independent multi-valued relationships are mixed together.

### After

```text id="8f4r2m"
          Student
          /     \
         /       \
        ↓         ↓
Student_Skill  Student_Hobby
```

### STUDENT_SKILL

```text id="w3f8kq"
Student | Skill
--------|--------
Ravi    | Java
Ravi    | Python
```

### STUDENT_HOBBY

```text id="s7n4vz"
Student | Hobby
--------|--------
Ravi    | Cricket
Ravi    | Music
```

This removes the unwanted independent combinations.

# 11. 4NF vs BCNF

This is an important interview comparison.

| BCNF                                                      | 4NF                                                        |
| --------------------------------------------------------- | ---------------------------------------------------------- |
| Deals mainly with functional dependencies                 | Deals with multivalued dependencies                        |
| Every determinant of a non-trivial FD must be a super key | Every determinant of a non-trivial MVD must be a super key |
| Stronger than 3NF                                         | Stronger than BCNF                                         |
| Focuses on functional dependency                          | Focuses on independent multi-valued relationships          |

### Memory trick

```text id="2h7v0m"
3NF  → Transitive Dependency
BCNF  → Determinant must be Super Key
4NF   → Multivalued Dependency
```

---

# 12. 3NF → BCNF → 4NF

Think of normalization as progressively handling different problems:

```text id="9r6x2p"
1NF
 ↓
Atomic Values
 ↓
2NF
 ↓
Partial Dependency
 ↓
3NF
 ↓
Transitive Dependency
 ↓
BCNF
 ↓
Determinant must be Super Key
 ↓
4NF
 ↓
Multivalued Dependency
```

# 13. Important Difference: Multiple Values vs Multiple Independent Values

This is a common confusion.

### 1NF problem

A cell contains multiple values:

| Student | Skills       |
| ------- | ------------ |
| Ravi    | Java, Python |

This violates the atomicity requirement of **1NF**.

---

### 4NF problem

Every cell can be atomic, but **two independent multi-valued relationships are stored together**:

| Student | Skill  | Hobby   |
| ------- | ------ | ------- |
| Ravi    | Java   | Cricket |
| Ravi    | Java   | Music   |
| Ravi    | Python | Cricket |
| Ravi    | Python | Music   |

This can create a **multivalued dependency** problem.

So:

```text id="b3w7fz"
1NF → Multiple values inside a cell
4NF → Multiple independent sets of values across rows
```

---

# 14. How to Identify a 4NF Violation

Follow these steps.

### Step 1

Check whether the relation is already in **BCNF**.

### Step 2

Identify multivalued dependencies.

Look for:

```text id="y1w4ka"
A →→ B
```

### Step 3

Ask:

> Are the multiple values of B independent of another multi-valued attribute?

If yes, investigate a possible 4NF violation.

### Step 4

Ask:

> Is A a super key?

If:

```text id="8f2d6x"
A = Super Key
```

the dependency does not violate the 4NF condition.

If:

```text id="m9c3vq"
A ≠ Super Key
```

then:

```text id="2s7h5n"
❌ 4NF violation
```

---

# 15. Common Confusions

### ❌ "4NF means no column can have multiple values."

That is primarily the **1NF** concept.

4NF deals with **multivalued dependencies between attributes**.

---

### ❌ "4NF is the same as BCNF."

No.

BCNF deals with **functional dependencies**.

4NF additionally handles **multivalued dependencies**.

---

### ❌ "Every table must be in 4NF."

Not necessarily.

Whether decomposition to 4NF is appropriate depends on the dependencies and the database design.

**Answer:**

It is represented as:

```text id="8r2q7m"

```

### Q3. What does 4NF remove?

**Answer:**

---

### Q4. What is the difference between FD and MVD?

**Answer:**

```text id="f2k8ya"
FD  →  A → B
MVD →  A →→ B
```

Functional dependency describes determination of an attribute, while multivalued dependency describes multiple independent values.

---

### Q5. Is 4NF stronger than BCNF?

**Answer:**

Yes. 4NF is a stronger normal form that additionally handles multivalued dependencies.

---

### Q6. What is the main rule of 4NF?

**Answer:**

> For every non-trivial multivalued dependency `X →→ Y`, `X` must be a super key.

---

# 17. Interview-Ready Answer

> **4NF, or Fourth Normal Form, is a higher level of normalization that deals with multivalued dependencies. A relation is in 4NF if it is in BCNF and, for every non-trivial multivalued dependency X →→ Y, X is a super key. 4NF helps eliminate redundancy caused by independent multi-valued relationships by separating them into different tables.**
