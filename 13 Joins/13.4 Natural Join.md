# 13.4 Natural Join

## 1. What is a Natural Join?

A **Natural Join** is a join that automatically performs the matching between two tables using their **common column names**.

The important point is:

> **Natural Join automatically finds columns having the same name in both tables and uses them for joining.**

You **do not write the joining condition** yourself.



---

# 2. Simple Example

Suppose we have two tables.

### Table 1

|  A |  B |
| -: | -: |
|  1 |  2 |
|  3 |  4 |
|  5 |  6 |
|  7 |  8 |

### Table 2

|  B |  C |
| -: | -: |
|  2 |  1 |
|  8 |  1 |
|  9 |  1 |

Look carefully.

Both tables contain a column named:

```text id="u1wqj5"
B
```

Therefore, Natural Join automatically uses:

```text id="8x7m9k"
Table1.B = Table2.B
```

It finds:

```text id="f9m1qy"
2 = 2 ✓
8 = 8 ✓
```

So the matching records are obtained.

---

# 3. Syntax

### Question

**What is the syntax of a Natural Join?**

### Answer / Query

```sql id="4q7y0w"
SELECT *
FROM Table1
NATURAL JOIN Table2;
```



Notice something very important:

There is **no `ON` clause**.

We don't write:

```sql id="0o5j5g"
ON Table1.B = Table2.B
```

because Natural Join automatically determines the common column.

---

# 4. How Does Natural Join Work?

Suppose:

```text id="n4gl4f"
Table1
A
B
```

and:

```text id="5f6q7s"
Table2
B
C
```

Both tables have:

```text id="zj1q4p"
B
```

Natural Join automatically understands:

```text id="l5d7um"
Table1.B = Table2.B
```

Then it performs the matching.

---

# 5. Natural Join Removes the Duplicate Common Column

This is an important feature.

With a normal Inner Join, the common column can appear twice:

```text
A | B | B | C
```

But Natural Join keeps **only one copy** of the identically named common column.

The example result is:

```text id="9f3m1v"
B | A | C
2 | 1 | 1
8 | 7 | 1
```



So:

```text id="8c4t0s"
Inner Join:
A  B  B  C

Natural Join:
B  A  C
```

The duplicate `B` is removed.

---

# 6. Natural Join with EMP and DEPT

`EMP` and `DEPT` have the same column name:

```text id="7s3k9a"
DEPT_ID
```

Therefore, Natural Join can automatically use `DEPT_ID`.

### Question

**Display the matching employee and department records using Natural Join.**

### Answer / Query

```sql id="4f6m2z"
SELECT *
FROM EMP
NATURAL JOIN DEPT;
```

Oracle automatically looks for the common column name:

```text id="q0w8x1"
EMP.DEPT_ID
        =
DEPT.DEPT_ID
```

You don't need to write an `ON` condition.

---

# 7. No `ON` Clause

This is one of the most important points for interviews.

### Inner Join

```sql id="h5b0s4"
SELECT *
FROM EMP e
INNER JOIN DEPT d
ON e.DEPT_ID = d.DEPT_ID;
```

Here we explicitly tell Oracle:

```text id="9n6x2c"
e.DEPT_ID = d.DEPT_ID
```

### Natural Join

```sql id="v1x8k3"
SELECT *
FROM EMP
NATURAL JOIN DEPT;
```

Here we don't specify:

```text id="0r7c2n"
ON ...
```

Oracle automatically identifies the common column name.

---

# 8. Important Rule

For Natural Join to work as intended:

```text id="5j2w7p"
Table 1
   ↓
Common column name
   ↑
Table 2
```

The columns used for the natural relationship must have the **same name** in both tables.

For example:

```text id="q2e7az"
EMP.DEPT_ID
DEPT.DEPT_ID
```

Both are named:

```text id="c5n4kx"
DEPT_ID
```

So they can be used automatically.

---

# 9. Natural Join vs Inner Join

| Inner Join                                 | Natural Join                           |
| ------------------------------------------ | -------------------------------------- |
| You specify the joining condition          | Oracle determines the common columns   |
| Uses `ON` in the syntax                    | No `ON` clause                         |
| Example: `ON e.DEPT_ID = d.DEPT_ID`        | Automatically uses common column names |
| Common columns can appear from both tables | Duplicate common column is removed     |

---

# 10. Natural Join vs Equi Join

| Equi Join                               | Natural Join                                   |
| --------------------------------------- | ---------------------------------------------- |
| Uses `=` explicitly                     | Equality condition is automatically determined |
| Joining condition is written in `WHERE` | No joining condition is written                |
| Example: `WHERE e.DEPT_ID = d.DEPT_ID`  | `NATURAL JOIN`                                 |
| Developer specifies the relationship    | Oracle identifies common column names          |

---

# 11. Very Important Confusion

### Don't write this for Natural Join:

```sql id="1l4p3q"
SELECT *
FROM EMP
NATURAL JOIN DEPT
ON EMP.DEPT_ID = DEPT.DEPT_ID;
```

❌ This is not the Natural Join syntax being taught here.

Instead:

```sql id="8n2v6c"
SELECT *
FROM EMP
NATURAL JOIN DEPT;
```

The joining condition is automatically determined.

---

# 12. Easy Memory Trick

Remember:

```text id="7z4p9m"
NATURAL JOIN
     ↓
Natural = Automatic
     ↓
Find same column name
     ↓
Join automatically
     ↓
Remove duplicate common column
```

### One-line definition

> **Natural Join automatically joins tables using identically named common columns and keeps only one copy of the common column.**

# 13. Interview Questions

### Q1. What is a Natural Join?

**Answer:**
A Natural Join automatically joins tables using common columns having the same name.

### Q2. Do we use `ON` with Natural Join?

**Answer:**
**No.** The joining condition is not explicitly given.

### Q3. How does Natural Join identify the joining column?

**Answer:**
It identifies the common columns having the same name in the tables.

### Q4. What happens to duplicate common columns?

**Answer:**
Natural Join keeps only **one copy** of the common column. 

### Q5. What common column can be used between EMP and DEPT?

**Answer:**

```text
DEPT_ID
```

### Q6. Give the syntax of Natural Join.

**Answer:**

```sql id="1l4r6a"
SELECT *
FROM Table1
NATURAL JOIN Table2;
```
