# 14.2.2.7-Add-Constraint

## 1. What is ADD CONSTRAINT?

A **constraint** is a rule that can be applied to a table's column(s) to control the data stored in the table.

When a table already exists, we can add a constraint to it using:

```sql
ALTER TABLE
```

So, **ADD CONSTRAINT** means:

> Add a new constraint to an existing table.

---

# 2. Why do we need ADD CONSTRAINT?

Suppose a table has already been created:

```text
BANK_DETAILS
```

and later we decide that the `BID` column must be a **Primary Key**.

Instead of creating the table again, we can add the constraint to the existing table.

```text
Existing table
      ↓
ALTER TABLE
      ↓
ADD CONSTRAINT
      ↓
Apply a rule
```

---

# 3. Syntax

### Question

**What is the syntax for adding a constraint to an existing table?**

### Syntax

```sql
ALTER TABLE table_name
ADD CONSTRAINT constraint_name
constraint_type(column_name);
```

The important parts are:

| Part              | Meaning                                   |
| ----------------- | ----------------------------------------- |
| `ALTER TABLE`     | Modifies an existing table                |
| `table_name`      | Name of the table                         |
| `ADD CONSTRAINT`  | Adds a new constraint                     |
| `constraint_name` | Name given to the constraint              |
| `constraint_type` | Type of constraint                        |
| `column_name`     | Column on which the constraint is applied |

---

# 4. Example — Adding a Primary Key

### Question

**Add a primary key constraint named `b_pk` on the `bid` column of the `Bank_Details` table.**

### Query

```sql
ALTER TABLE Bank_Details
ADD CONSTRAINT b_pk
PRIMARY KEY(bid);
```

### What happens?

The existing table:

```text
BANK_DETAILS
```

gets a constraint:

```text
b_pk
  ↓
PRIMARY KEY
  ↓
BID
```

Now `BID` is treated as the primary key of the table.

# 6. Why give a Constraint a Name?

A constraint can be given a name so that it can be referred to later.

For example:

```text
b_pk
```

is the name of the primary key constraint.

Later, if we want to remove this constraint, we can refer to its name.

### Question

**If the primary key constraint was named `b_pk`, what name would we use when dropping that constraint?**

### Answer

```text
b_pk
```

This connects the two operations:

```text
ADD CONSTRAINT
      ↓
    b_pk
      ↓
DROP CONSTRAINT
      ↓
    b_pk
```

---

# 7. ADD CONSTRAINT vs DROP CONSTRAINT

| ADD CONSTRAINT                  | DROP CONSTRAINT                    |
| ------------------------------- | ---------------------------------- |
| Adds a constraint               | Removes a constraint               |
| Uses `ADD CONSTRAINT`           | Uses `DROP CONSTRAINT`             |
| Creates a rule on the table     | Removes an existing rule           |
| Needs the constraint definition | Needs the existing constraint name |

### Add

### Question

**Add the primary key constraint `b_pk` on `bid`.**

### Query

```sql
ALTER TABLE Bank_Details
ADD CONSTRAINT b_pk
PRIMARY KEY(bid);
```

### Drop

### Question

**Remove the constraint named `b_pk` from `Bank_Details`.**

### Query

```sql
ALTER TABLE Bank_Details
DROP CONSTRAINT b_pk;
```

---

# 8. ADD CONSTRAINT vs CREATE TABLE Constraint

There are two different situations.

### Situation 1 — Creating a new table

A constraint can be defined while creating the table.

### Situation 2 — Table already exists

We can add a constraint later using:

```sql
ALTER TABLE
ADD CONSTRAINT
```

So:

```text
New table
   ↓
CREATE TABLE
   ↓
Constraint can be defined
```

Whereas:

```text
Existing table
   ↓
ALTER TABLE
   ↓
ADD CONSTRAINT
```

---

# 9. Important Points

### 1. The table must already exist

`ALTER TABLE` works with an existing table.

### 2. Give the constraint a name

Example:

```text
b_pk
```

### 3. Specify the constraint type

For example:

```text
PRIMARY KEY
```

### 4. Specify the column

Example:

```text
BID
```

### 5. The constraint name can be used later

For example, to remove `b_pk`:

```sql
ALTER TABLE Bank_Details
DROP CONSTRAINT b_pk;
```

# 10. Common Mistake

### Incorrect

```sql
ALTER TABLE Bank_Details
ADD PRIMARY KEY(bid);
```

The form being used here is missing the explicitly named constraint.

### Correct

```sql
ALTER TABLE Bank_Details
ADD CONSTRAINT b_pk
PRIMARY KEY(bid);
```

Remember the pattern:

```text
ADD CONSTRAINT
      ↓
constraint name
      ↓
constraint type
      ↓
column
```
