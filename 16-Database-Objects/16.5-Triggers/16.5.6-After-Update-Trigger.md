# 16.5.6-After-Update-Trigger

## 1. What is an AFTER UPDATE Trigger?

An **AFTER UPDATE Trigger** is a Trigger whose action is executed **after an existing row has been updated**.

Break the name into two parts:

```text
AFTER  → When?
UPDATE → Which event?
```

So the flow is:

```text
UPDATE happens
      ↓
AFTER UPDATE Trigger executes
      ↓
Trigger Action
```

Triggers are saved in the database and execute autonomously when the specified event occurs.

---

## 2. Why is it called AFTER UPDATE?

Because the **UPDATE operation happens first**, and the Trigger action happens afterward.

```text
BEFORE UPDATE

Trigger Action
      ↓
UPDATE
```

Whereas:

```text
AFTER UPDATE

UPDATE
  ↓
Trigger Action
```

### Easy memory

> **BEFORE UPDATE → Trigger first, UPDATE next**
> **AFTER UPDATE → UPDATE first, Trigger next**

---

## 3. General Syntax

### Question:

What is the syntax for creating an AFTER UPDATE Trigger?

### Answer / Syntax:

```sql
CREATE TRIGGER trigger_name
AFTER UPDATE
ON table_name
FOR EACH ROW
BEGIN
    SQL Query;
END;
```

The Trigger syntax specifies the timing, event, table, and SQL action.

---

## 4. Understanding the Syntax

| Part             | Meaning                          |
| ---------------- | -------------------------------- |
| `CREATE TRIGGER` | Creates a Trigger                |
| `trigger_name`   | Name of the Trigger              |
| `AFTER`          | Action occurs after the event    |
| `UPDATE`         | Event that activates the Trigger |
| `ON table_name`  | Table on which UPDATE occurs     |
| `FOR EACH ROW`   | Applies to each affected row     |
| `BEGIN`          | Starts Trigger body              |
| `SQL Query`      | Action performed by Trigger      |
| `END`            | Ends Trigger                     |

# 5. `:OLD` and `:NEW` in UPDATE

UPDATE is different from INSERT and DELETE because both the **old value** and **new value** can be available.

The mapping is:

```text
INSERT → :NEW
UPDATE → :OLD + :NEW
DELETE → :OLD
```

For example:

```text
Before UPDATE:
Salary = 20,000
       ↓
   :OLD.salary

After UPDATE:
Salary = 25,000
       ↓
   :NEW.salary
```

So:

| Reference | Meaning                          |
| --------- | -------------------------------- |
| `:OLD`    | Value before UPDATE              |
| `:NEW`    | New value associated with UPDATE |

# 6. Example of an AFTER UPDATE Trigger

### Question:

Create an AFTER UPDATE Trigger on `table1`.

### Answer / Query:

```sql
CREATE TRIGGER dec
AFTER UPDATE
ON table1
FOR EACH ROW
BEGIN
    -- SQL action
END;
```

The important part is:

```sql
AFTER UPDATE
```

This tells us:

```text
Timing = AFTER
Event  = UPDATE
```

# 7. Example of an UPDATE Event

### Question:

Update the salary of an employee in `emp1`.

### Answer / Query:

```sql
UPDATE emp1
SET salary = 25000
WHERE emp_id = 101;
```

If an AFTER UPDATE Trigger exists on `emp1`, the execution flow is:

```text
UPDATE emp1
     ↓
Row is updated
     ↓
AFTER UPDATE Trigger
     ↓
Trigger Action executes
```

The key point is that the **UPDATE happens before the Trigger action**.

# 8. Event and Action

### Question:

In an AFTER UPDATE Trigger, identify the timing, event, and action.

### Answer:

**Timing:**

```text
AFTER
```

**Event:**

```text
UPDATE
```

**Action:**

```text
SQL statement written inside the Trigger
```

Therefore:

```text
AFTER UPDATE
      ↓
UPDATE event occurs
      ↓
Trigger action executes
```

# 9. BEFORE UPDATE vs AFTER UPDATE

| BEFORE UPDATE                                   | AFTER UPDATE                                    |
| ----------------------------------------------- | ----------------------------------------------- |
| Trigger action occurs before UPDATE             | Trigger action occurs after UPDATE              |
| Timing = BEFORE                                 | Timing = AFTER                                  |
| Event = UPDATE                                  | Event = UPDATE                                  |
| `:OLD` and `:NEW` can be associated with UPDATE | `:OLD` and `:NEW` can be associated with UPDATE |

### Visual memory

```text
BEFORE UPDATE

BEFORE Trigger
      ↓
UPDATE
```

```text
AFTER UPDATE

UPDATE
  ↓
AFTER Trigger
```

---

# 10. UPDATE and Its Row References

### Question:

Which row references are associated with an UPDATE event?

### Answer:

```text
:OLD
:NEW
```

This means we can understand the change as:

```text
:OLD → previous value
:NEW → new value
```

Example:

```text
Salary before update = 20,000
                         ↓
                    :OLD.salary

Salary after update = 25,000
                         ↓
                    :NEW.salary
```

---

# 11. Important Points

* `AFTER UPDATE` is one of the six Trigger combinations.
* `AFTER` specifies the timing.
* `UPDATE` specifies the event.
* The UPDATE happens first.
* The Trigger action executes afterward.
* UPDATE uses both `:OLD` and `:NEW`.
* `:OLD` represents the value before the UPDATE.
* `:NEW` represents the new value associated with the UPDATE.
