# 13.5.3 Full Outer Join

## 1. What is a Full Outer Join?

A **Full Outer Join** combines two tables and returns:

> **All matching and non-matching records from both tables.**

In simple words:

```text id="1t7n4a"
FULL OUTER JOIN
       ↓
ALL LEFT ROWS
       +
ALL RIGHT ROWS
```

So it combines the behavior of:

```text id="h2x3d1"
LEFT OUTER JOIN
        +
RIGHT OUTER JOIN
```

It is described as a combination of Left Outer Join and Right Outer Join. 

---

# 2. Simple Example

Consider these two tables.

### Table 7 — Left Table

|  A |  B |
| -: | -: |
|  1 |  2 |
|  3 |  4 |
|  5 |  6 |
|  7 |  8 |

### Table 8 — Right Table

|  B |  C |
| -: | -: |
|  2 |  1 |
|  8 |  1 |
|  9 |  1 |

The common column is:

```text id="7y6y1u"
B
```

Now compare them:

```text id="f4j9hc"
LEFT TABLE       RIGHT TABLE

B = 2    ←→      B = 2     ✓ MATCH
B = 4              --       ✗
B = 6              --       ✗
B = 8    ←→      B = 8     ✓ MATCH
                   B = 9     ✗
```

Because this is a **Full Outer Join**, we keep **everything from both sides**.

---

# 3. Result

### Question

**Perform a Full Outer Join between Table 7 and Table 8 using column `B`.**

### Answer / Query

```sql id="7g0w8e"
SELECT *
FROM Table7
FULL OUTER JOIN Table8
ON Table7.B = Table8.B;
```

### Result

|  A |  B |  B |  C |
| -: | -: | -: | -: |
|  1 |  2 |  2 |  1 |
|  3 |  4 |  - |  - |
|  5 |  6 |  - |  - |
|  7 |  8 |  8 |  1 |
|  - |  - |  9 |  1 |

This includes:

* Matching row `2`
* Matching row `8`
* Non-matching left rows `4` and `6`
* Non-matching right row `9`



---

# 4. Why are `4` and `6` present?

Look at the left table:

```text id="4zv1bx"
B
2
4
6
8
```

The values `4` and `6` don't exist in the right table.

Normally, an Inner Join would remove them.

But Full Outer Join keeps **all rows from the left table**.

Therefore:

```text id="9y3z2e"
3 | 4 | - | -
5 | 6 | - | -
```

are included.

---

# 5. Why is `9` present?

The right table contains:

```text id="q9cv9c"
B
2
8
9
```

`9` doesn't exist in the left table.

A Right Outer Join would preserve it.

A Full Outer Join also preserves it because it keeps **all rows from both tables**.

Therefore:

```text id="i7r3kq"
- | - | 9 | 1
```

is included.

---

# 6. Understand Full Outer Join Visually

```text id="5krm0s"
             FULL OUTER JOIN

        LEFT TABLE       RIGHT TABLE
             │                │
             │                │
             ├── MATCH ───────┤
             │                │
             ↓                ↓
        ALL LEFT          ALL RIGHT
             │                │
             └──────┬─────────┘
                    ↓
              COMPLETE RESULT
```

So:

```text id="j1i6bq"
LEFT ONLY       → KEEP
RIGHT ONLY      → KEEP
MATCHING        → KEEP
```

That is the core idea.

# 7. Syntax

### Question

**What is the syntax of a Full Outer Join?**

### Answer / Query

```sql id="k9k1g7"
SELECT */attribute
FROM Table1
FULL OUTER JOIN Table2
ON Table1.B = Table2.B;
```



Break it down:

```sql id="l2h8sp"
SELECT *
```

→ Select the required columns.

```sql id="9jv0v2"
FROM Table1
```

→ `Table1` is the left table.

```sql id="4q7x4e"
FULL OUTER JOIN Table2
```

→ Keep rows from both tables.

```sql id="u5x6p9"
ON Table1.B = Table2.B
```

→ Match the tables using column `B`.

# 8. EMP and DEPT Example

The common column is:

```text id="2v3z9j"
DEPT_ID
```

So:

```text id="6e7d2w"
EMP.DEPT_ID = DEPT.DEPT_ID
```

### Question

**Perform an EMP table Full Outer Join with the DEPT table using DEPT_ID.**

### Answer / Query

```sql id="e8m5h2"
SELECT *
FROM EMP
FULL OUTER JOIN DEPT
ON EMP.DEPT_ID = DEPT.DEPT_ID;
```

This exact type of operation is included in the SQL material. 

Here:

```text id="q3m5tp"
EMP  → LEFT TABLE
DEPT → RIGHT TABLE
```

Full Outer Join keeps:

```text id="x3x8pd"
ALL EMP ROWS
      +
ALL DEPT ROWS
```

Matching rows are combined.

Non-matching rows from either table are also retained.

---

# 9. Full Outer Join vs Inner Join

### Inner Join

```sql id="af5h4p"
SELECT *
FROM EMP e
INNER JOIN DEPT d
ON e.DEPT_ID = d.DEPT_ID;
```

Returns:

```text id="7wq0ad"
MATCHING RECORDS ONLY
```

### Full Outer Join

```sql id="4cv0m2"
SELECT *
FROM EMP e
FULL OUTER JOIN DEPT d
ON e.DEPT_ID = d.DEPT_ID;
```

Returns:

```text id="g3p1mm"
MATCHING RECORDS
       +
NON-MATCHING EMP RECORDS
       +
NON-MATCHING DEPT RECORDS
```

---

# 10. Full Outer Join vs Left Outer Join

| Left Outer Join                        | Full Outer Join                     |
| -------------------------------------- | ----------------------------------- |
| Keeps all left rows                    | Keeps all left rows                 |
| Keeps matching right rows              | Keeps matching right rows           |
| Does not preserve unmatched right rows | **Also keeps unmatched right rows** |

Example:

```text id="zv4r7k"
LEFT JOIN
    ↓
ALL LEFT + MATCHING RIGHT
```

```text id="9q3w2s"
FULL JOIN
    ↓
ALL LEFT + ALL RIGHT
```

---

# 11. Full Outer Join vs Right Outer Join

| Right Outer Join                      | Full Outer Join                    |
| ------------------------------------- | ---------------------------------- |
| Keeps all right rows                  | Keeps all right rows               |
| Keeps matching left rows              | Keeps matching left rows           |
| Does not preserve unmatched left rows | **Also keeps unmatched left rows** |

---

# 12. Important Point from the Example

The result is larger because **both tables' unmatched records are retained**.

For the example:

```text id="4w4x8s"
Table 1 → 4 rows
Table 2 → 3 rows
```

The result contains:

```text id="p3b0eq"
2 matching rows
+
2 left-only rows
+
1 right-only row
```

So:

```text id="m8j4yq"
5 result rows
```

# 13. Important Rules

### Rule 1

Full Outer Join returns matching records.

### Rule 2

It also returns non-matching records from the left table.

### Rule 3

It also returns non-matching records from the right table.

### Rule 4

The joining condition is normally specified using `ON`.

Example:

```sql id="3ov0r5"
ON EMP.DEPT_ID = DEPT.DEPT_ID
```

### Rule 5

Full Outer Join is a combination of:

```text id="d2q9v4"
LEFT OUTER JOIN
        +
RIGHT OUTER JOIN
```

# 14. Interview Questions

### Q1. What is a Full Outer Join?

**Answer:**
A Full Outer Join returns matching and non-matching records from both tables.

### Q2. Does Full Outer Join return unmatched rows from the left table?

**Answer:**
**Yes.**

### Q3. Does Full Outer Join return unmatched rows from the right table?

**Answer:**
**Yes.**

### Q4. Which joins are combined to form a Full Outer Join?

**Answer:**
Left Outer Join and Right Outer Join.

### Q5. What happens to unmatched records?

**Answer:**
Unmatched records from **both tables are retained**.

### Q6. What happens when two rows match?

**Answer:**
Their data is combined into the result.

### Q7. What is the main difference between Inner Join and Full Outer Join?

**Answer:**

```text id="y9y0av"
INNER JOIN
→ Matching only

FULL OUTER JOIN
→ Matching + non-matching from both tables
```

# 15. Easy Memory Trick

Remember the three Outer Joins:

```text id="z9r5xq"
LEFT OUTER JOIN
       ↓
   ALL LEFT


RIGHT OUTER JOIN
       ↓
   ALL RIGHT


FULL OUTER JOIN
       ↓
   ALL BOTH
```

### Final formula

```text id="2x1x8g"
FULL OUTER JOIN
      =
ALL LEFT
   +
ALL RIGHT
```

> **Full Outer Join = Keep everything from both tables, whether the rows match or not.**
