# 13.5.1 Left Outer Join

## 1. What is a Left Outer Join?

A **Left Outer Join** combines two tables and returns:

> **All rows from the left table + only matching rows from the right table.**

This is the most important rule.

```text
LEFT TABLE                    RIGHT TABLE
    │                              │
    │                              │
    ├── ALL ROWS ────────────────→ │
    │                              │
    │                    matching rows only
```

The left table is always completely preserved. 

---

# 2. Simple Example

Consider these two tables.

### Table 3 — Left Table

|  A |  B |
| -: | -: |
|  1 |  2 |
|  3 |  4 |
|  5 |  6 |
|  7 |  8 |

### Table 4 — Right Table

|  B |  C |
| -: | -: |
|  2 |  1 |
|  8 |  1 |
|  9 |  1 |

The common column is `B`.

Let's compare:

```text
id="7rjv8m"
Left B     Right B
------     -------
2     →    2    ✓
4     →    no   ✗
6     →    no   ✗
8     →    8    ✓
```

There is also `9` in the right table, but it has no matching value in the left table.

---

# 3. What does Left Outer Join keep?

Remember:

```text
LEFT OUTER JOIN
       ↓
ALL LEFT ROWS
       +
MATCHING RIGHT ROWS
```

Therefore:

* `1,2` → kept
* `3,4` → kept
* `5,6` → kept
* `7,8` → kept
* Right-side `9,1` → not included because there is no matching left row

The unmatched right-side values are not preserved.

---

# 4. Syntax

### Question

**What is the syntax of a Left Outer Join?**

### Answer / Query

```sql
SELECT */attribute
FROM Table1
LEFT OUTER JOIN Table2
ON Table1.B = Table2.B;
```



Here:

```text
Table1 → LEFT TABLE
Table2 → RIGHT TABLE
```

The important part is:

```sql
ON Table1.B = Table2.B
```

This tells Oracle which column should be used for matching.

---

# 5. Short Syntax

`OUTER` can be omitted.

### Question

**Can we write Left Outer Join without the word `OUTER`?**

### Answer / Query

```sql
SELECT */attribute
FROM Table1
LEFT JOIN Table2
ON Table1.B = Table2.B;
```

This is the shorter form shown in the material. 

So both forms are:

```sql
LEFT OUTER JOIN
```

and

```sql
LEFT JOIN
```

# 7. What happens to the unmatched rows?

Look at:

```text
Left Table B
2
4
6
8
```

Right Table B:

```text
2
8
9
```

Matches:

```text
2 → match
8 → match
```

Unmatched left rows:

```text
4
6
```

Because this is a **Left Outer Join**, `4` and `6` are still present.

Their right-side columns have no matching data.

Conceptually:

```text
3 | 4 | - | -
5 | 6 | - | -
```

# 8. EMP and DEPT Example

The common column between `EMP` and `DEPT` is:

```text
DEPT_ID
```

So we can join:

```text
EMP.DEPT_ID = DEPT.DEPT_ID
```

### Question

**Perform a Left Outer Join between EMP and DEPT using DEPT_ID.**

### Answer / Query

```sql
SELECT *
FROM EMP e
LEFT OUTER JOIN DEPT d
ON e.DEPT_ID = d.DEPT_ID;
```

Here:

```text
EMP  → LEFT TABLE
DEPT → RIGHT TABLE
```

Therefore:

```text
ALL EMP ROWS
      +
MATCHING DEPT ROWS
```

If an employee's `DEPT_ID` has no matching department, the employee's row is still returned.

---

# 9. Very Important: Which Table is "Left"?

Look at the query:

```sql
FROM EMP e
LEFT OUTER JOIN DEPT d
```

The table before `LEFT OUTER JOIN` is the **left table**.

So:

```text
EMP → LEFT
DEPT → RIGHT
```

But if we write:

```sql
FROM DEPT d
LEFT OUTER JOIN EMP e
```

then:

```text
DEPT → LEFT
EMP → RIGHT
```

Therefore, **position matters**.

# 10. Left Join vs Inner Join

### Question

**What is the difference between Inner Join and Left Outer Join?**

### Inner Join

```sql
SELECT *
FROM EMP e
INNER JOIN DEPT d
ON e.DEPT_ID = d.DEPT_ID;
```

Returns:

```text
MATCHING ROWS ONLY
```

### Left Outer Join

```sql
SELECT *
FROM EMP e
LEFT OUTER JOIN DEPT d
ON e.DEPT_ID = d.DEPT_ID;
```

Returns:

```text
ALL EMP ROWS
+
MATCHING DEPT ROWS
```

### Easy comparison

| Inner Join                   | Left Outer Join                   |
| ---------------------------- | --------------------------------- |
| Matching rows only           | All left rows                     |
| Unmatched left rows removed  | Unmatched left rows retained      |
| Unmatched right rows removed | Unmatched right rows not retained |

---

# 11. Left vs Right Outer Join

This is a very common confusion.

| Left Outer Join                   | Right Outer Join                   |
| --------------------------------- | ---------------------------------- |
| Keeps all rows from LEFT table    | Keeps all rows from RIGHT table    |
| Matching right rows included      | Matching left rows included        |
| Left side is completely preserved | Right side is completely preserved |

### Memory trick

```text
LEFT JOIN
   ↓
Keep LEFT

RIGHT JOIN
   ↓
Keep RIGHT
```

# 13. Interview Questions

### Q1. What is a Left Outer Join?

**Answer:**
A Left Outer Join returns all rows from the left table and only matching rows from the right table.

### Q2. Which table is completely preserved in a Left Outer Join?

**Answer:**
The **left table**.

### Q3. Does a Left Outer Join return unmatched rows from the left table?

**Answer:**
**Yes.**

### Q4. Does it return unmatched rows from the right table?

**Answer:**
**No.**

### Q5. Can we write `LEFT JOIN` instead of `LEFT OUTER JOIN`?

**Answer:**
Yes.

```sql
LEFT JOIN
```

is the shorter form of:

```sql
LEFT OUTER JOIN
```

### Q6. Where do we specify the matching condition?

**Answer:**
In the `ON` clause.

Example:

```sql
ON e.DEPT_ID = d.DEPT_ID
```

# 14. Easy Memory Trick

```text
LEFT OUTER JOIN
       ↓
     LEFT
       ↓
KEEP EVERYTHING
       ↓
   + MATCHING
     RIGHT
```

### One-line definition

> **Left Outer Join = All rows from the left table + matching rows from the right table.**
