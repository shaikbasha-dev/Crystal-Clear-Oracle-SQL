# 16.3.3-When-Not-to-Create-Index

An Index is **not suitable in certain situations**. There are **three important conditions** to remember.

---

## 1. When the Data is Very Small

If the table contains a **very small amount of data**, creating an Index is not suitable.

### Simple idea

```text
Small amount of data
        ↓
Less data to search
        ↓
Index is not necessary
```

The smaller the table, the less benefit we get from an Index. 

---

## 2. When the Column is Not Frequently Used as a Condition

If a column is **not frequently used as a condition** while retrieving data, creating an Index on that column is not suitable.

For example, if `dept_id` is rarely used in conditions such as:

### Question:

Retrieve employees based on department ID.

### Query:

```sql id="u5a2h9"
SELECT *
FROM emp
WHERE dept_id = 22;
```

If `dept_id` is **not frequently used** as a condition, an Index on that column is not suitable according to the given rule. 

---

## 3. When the Table is Updated Frequently

If a table is **updated frequently**, creating an Index is not suitable.

### Simple idea

```text
Table
  ↓
Frequent updates
  ↓
Index is not suitable
```

The given condition specifically says that an Index is not suitable when the table is updated frequently. 

---

# 4. All Three Conditions

| Situation                                    | Create Index? |
| -------------------------------------------- | ------------- |
| Data is very small                           | ❌ No          |
| Column is not frequently used as a condition | ❌ No          |
| Table is updated frequently                  | ❌ No          |

---

# 5. Suitable vs Not Suitable

| Create Index                                 | Don't Create Index                               |
| -------------------------------------------- | ------------------------------------------------ |
| Data is **very large**                       | Data is **very small**                           |
| Column is **frequently used as a condition** | Column is **not frequently used as a condition** |
| Table is **not updated frequently**          | Table is **updated frequently**                  |



---

# 6. Easy Memory Trick

Remember:

```text id="xqj5m8"
       DON'T CREATE INDEX
                │
       ┌────────┼────────┐
       ↓        ↓        ↓
     SMALL    RARE     MANY
     DATA    CONDITION UPDATES
```

### **S → R → M**

> **Small Data + Rarely used condition column + Many Updates = Don't create Index**

---

# 7. Interview Questions

### Q1. When should we not create an Index?

**Answer:**

An Index is not suitable:

1. When the data is very small.
2. When the column is not frequently used as a condition.
3. When the table is updated frequently.

### Q2. Is an Index suitable for a small table?

**Answer:**
No. When the data is very small, creating an Index is not suitable.

### Q3. Is an Index suitable for a frequently updated table?

**Answer:**
No. When the table is updated frequently, creating an Index is not suitable.

### Q4. Should we create an Index on a column that is rarely used as a condition?

**Answer:**
No. The given rule says an Index is not suitable when the column is not frequently used as a condition.

---

## 8. Interview-Ready Answer

> **An Index is not suitable when the data is very small, the column is not frequently used as a condition, or the table is updated frequently.**
