# 19.6-Third-Normal-Form-3NF

## 1. What is 3NF?

**3NF (Third Normal Form)** is the third level of database normalization.

A table is in **3NF** when:

1. The table is already in **2NF**.
2. There is **no Transitive Functional Dependency**.

### Simple definition

> **3NF = 2NF + No Transitive Dependency**

The main idea is:

> A non-key attribute should not depend on another non-key attribute.

---

# 2. First Understand Transitive Dependency

Consider this table:

| Student_ID | Student_Name | Department_ID | Department_Name  |
| ---------: | ------------ | ------------- | ---------------- |
|        101 | Ravi         | D01           | Computer Science |
|        102 | Anil         | D01           | Computer Science |
|        103 | Sara         | D02           | Mathematics      |

Assume:

```text id="7a9d2u"
Student_ID
```

is the primary key.

Now look at the dependencies.

### Dependency 1

Student ID determines student name:

```text id="j4x7cb"
Student_ID → Student_Name
```

### Dependency 2

Student ID also determines department ID:

```text id="b2s3dd"
Student_ID → Department_ID
```

### Dependency 3

Department ID determines department name:

```text id="v2h9d7"
Department_ID → Department_Name
```

Therefore:

```text id="h1r8cc"
Student_ID
     ↓
Department_ID
     ↓
Department_Name
```

`Department_Name` is indirectly dependent on `Student_ID` through `Department_ID`.

This is called **Transitive Dependency**.

---

# 3. What Exactly is Transitive Dependency?

A transitive dependency occurs when:

```text id="1p4f8a"
A → B
B → C
```

Therefore:

```text id="c9v4ye"
A → C
```

where `B` is an intermediate attribute.

In our example:

```text id="7y4f1p"
Student_ID → Department_ID
Department_ID → Department_Name
```

Therefore:

```text id="f8m2qk"
Student_ID → Department_Name
```

through `Department_ID`.

---

# 4. Why is Transitive Dependency a Problem?

Look at the table again:

| Student_ID | Student_Name | Department_ID | Department_Name  |
| ---------: | ------------ | ------------- | ---------------- |
|        101 | Ravi         | D01           | Computer Science |
|        102 | Anil         | D01           | Computer Science |
|        103 | Sara         | D02           | Mathematics      |

`Computer Science` is repeated.

Suppose the department name changes from:

```text
Computer Science
```

to:

```text Computer Science and Engineering
```

We need to update multiple rows.

If we update only one row:

| Student_ID | Student_Name | Department_ID | Department_Name                  |
| ---------: | ------------ | ------------- | -------------------------------- |
|        101 | Ravi         | D01           | Computer Science and Engineering |
|        102 | Anil         | D01           | Computer Science                 |
|        103 | Sara         | D02           | Mathematics                      |

Now the same department ID `D01` has two different names.

This creates **data inconsistency**.

This is one reason why transitive dependencies should be removed.

---

# 5. How Does 3NF Solve This?

Separate department information into its own table.

### STUDENT

| Student_ID | Student_Name | Department_ID |
| ---------: | ------------ | ------------- |
|        101 | Ravi         | D01           |
|        102 | Anil         | D01           |
|        103 | Sara         | D02           |

### DEPARTMENT

| Department_ID | Department_Name  |
| ------------- | ---------------- |
| D01           | Computer Science |
| D02           | Mathematics      |

Now:

```text id="d8p3zq"
STUDENT
Student_ID → Student_Name
Student_ID → Department_ID
```

and:

```text id="q0k7vf"
DEPARTMENT
Department_ID → Department_Name
```

`Department_Name` is no longer stored in the student table.

The transitive dependency has been removed from the student relation.

---

# 6. 3NF Step-by-Step

To understand 3NF easily, follow this process.

### Step 1 — Check 1NF

The table must have atomic values.

```text
1NF ✅
```

### Step 2 — Check 2NF

There must be no partial dependency.

```text
2NF ✅
```

### Step 3 — Check Transitive Dependency

Ask:

> Does a non-key attribute depend on another non-key attribute?

If **Yes**:

```text
❌ Not in 3NF
```

If **No**:

```text
✅ 3NF
```

---

# 7. Simple Formula

Remember:

```text id="w7j2mf"
3NF = 2NF + No Transitive Dependency
```

Or:

```text id="j8t3va"
1NF
 ↓
2NF
 ↓
3NF
```

Each level builds on the previous level.

# 8. SQL Example

## Question

Create a `Department` table to store department information separately.

### Answer / Query

```sql id="x5r1na"
CREATE TABLE Department
(
    Department_ID   VARCHAR2(10) PRIMARY KEY,
    Department_Name VARCHAR2(50)
);
```

### Output structure

| Department_ID | Department_Name  |
| ------------- | ---------------- |
| D01           | Computer Science |
| D02           | Mathematics      |

---

## Question

Create a `Student` table where the student stores only the department ID instead of repeating the department name.

### Answer / Query

```sql id="q9v6ct"
CREATE TABLE Student
(
    Student_ID   NUMBER PRIMARY KEY,
    Student_Name VARCHAR2(30),
    Department_ID VARCHAR2(10),

    FOREIGN KEY (Department_ID)
        REFERENCES Department(Department_ID)
);
```

Now the relationship is:

```text id="a4z8dy"
Student
   │
   │ Department_ID
   ↓
Department
```


# 11. Retrieve Student and Department Information

The information is now separated into two tables.

We can combine it using a `JOIN`.

## Question

Display each student's name along with the department name.

### Answer / Query

```sql id="y6w1zn"
SELECT s.Student_ID,
       s.Student_Name,
       d.Department_Name
FROM Student s
JOIN Department d
ON s.Department_ID = d.Department_ID;
```

### Output

| Student_ID | Student_Name | Department_Name  |
| ---------: | ------------ | ---------------- |
|        101 | Ravi         | Computer Science |
|        102 | Anil         | Computer Science |
|        103 | Sara         | Mathematics      |

The data is stored separately, but we can retrieve it together when required.

# 12. Before 3NF vs After 3NF

### Before 3NF

| Student_ID | Student_Name | Department_ID | Department_Name  |
| ---------: | ------------ | ------------- | ---------------- |
|        101 | Ravi         | D01           | Computer Science |
|        102 | Anil         | D01           | Computer Science |
|        103 | Sara         | D02           | Mathematics      |

Dependency:

```text id="q3d5cz"
Student_ID → Department_ID
Department_ID → Department_Name
```

Therefore:

```text id="8x1k3m"
Student_ID → Department_Name
```

through `Department_ID`.

❌ Transitive dependency exists.

---

### After 3NF

**Student**

| Student_ID | Student_Name | Department_ID |
| ---------: | ------------ | ------------- |
|        101 | Ravi         | D01           |
|        102 | Anil         | D01           |
|        103 | Sara         | D02           |

**Department**

| Department_ID | Department_Name  |
| ------------- | ---------------- |
| D01           | Computer Science |
| D02           | Mathematics      |

Now the department information is stored independently.

---

# 13. 2NF vs 3NF

| 2NF                                                                       | 3NF                                                                                               |
| ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Requires 1NF                                                              | Requires 2NF                                                                                      |
| Removes partial dependency                                                | Removes transitive dependency                                                                     |
| Mainly important with composite keys                                      | Deals with non-key → non-key dependency                                                           |
| `Student_ID → Student_Name` when Student_ID is only part of composite key | `Department_ID → Department_Name` where both are non-key attributes in the original Student table |

### Memory trick

```text
2NF → PARTIAL
3NF → TRANSITIVE
```

---

# 14. Very Important Example

Consider:

| Student_ID | Course_ID | Student_Name | Course_Name | Department_ID | Department_Name  | Marks |
| ---------: | --------- | ------------ | ----------- | ------------- | ---------------- | ----: |
|        101 | C01       | Ravi         | Java        | D01           | Computer Science |    80 |
|        101 | C02       | Ravi         | Python      | D01           | Computer Science |    90 |
|        102 | C01       | Anil         | Java        | D01           | Computer Science |    75 |

Composite key:

```text id="3u7k1q"
(Student_ID, Course_ID)
```

Functional dependencies include:

```text id="x8m2qa"
Student_ID → Student_Name
Course_ID → Course_Name
(Student_ID, Course_ID) → Marks
```

These first two are **partial dependencies**, so the table needs to be converted to 2NF first.

Then consider:

```text id="w3d6nc"
Student_ID → Department_ID
Department_ID → Department_Name
```

Therefore:

```text id="g5t1hr"
Student_ID → Department_Name
```

through `Department_ID`.

That is a **transitive dependency**.

So after dealing with 2NF, we need another decomposition to reach 3NF.

---

# 15. How to Identify 3NF in an Interview

Use this sequence:

```text
Step 1 → Is the table in 1NF?
Step 2 → Is the table in 2NF?
Step 3 → Is there a transitive dependency?
```

If:

```text
1NF ✅
2NF ✅
No Transitive Dependency ✅
```

then:

```text
3NF ✅
```

---

# 16. Common Confusions

### ❌ "3NF removes partial dependency."

No.

**2NF** removes partial dependency.

---

### ❌ "3NF means there should be no duplicate values."

Not exactly.

The main goal is to remove **transitive dependency**.

---

### ❌ "Every non-key column must depend directly on the primary key and nothing else."

This is a useful beginner-friendly way to think about 3NF, but the formal definition is expressed in terms of **candidate keys and non-prime attributes**.

---

### ❌ "3NF means we cannot use JOIN."

No.

Normalization often separates data into multiple related tables, and `JOIN` is then used to retrieve related information.

---

# 17. Interview Questions

### Q1. What is 3NF?

**Answer:**

> 3NF is the third normal form. A table must first be in 2NF and should not contain transitive functional dependencies.

### Q2. What is the main purpose of 3NF?

**Answer:**

> To remove transitive dependencies and reduce unnecessary repetition of data.

### Q3. What is transitive dependency?

**Answer:**

> Transitive dependency occurs when a non-key attribute depends on another non-key attribute.

Example:

```text
A → B
B → C
Therefore A → C
```

### Q4. Which normal form removes transitive dependency?

**Answer:**

**3NF.**

### Q5. What is the difference between 2NF and 3NF?

**Answer:**

> 2NF removes partial dependency, while 3NF removes transitive dependency.

### Q6. Does 3NF require 2NF?

**Answer:**

Yes. A table must satisfy the requirements of the previous normal forms before reaching 3NF.

---

# 18. Interview-Ready Answer

> **Third Normal Form (3NF) is achieved when a table is already in 2NF and has no transitive functional dependency. In other words, non-key attributes should not depend on other non-key attributes. 3NF helps reduce data redundancy and update-related problems by separating independently dependent information into appropriate tables.**

---

# 19. Complete Normalization Flow So Far

```text
             UNNORMALIZED TABLE
                    │
                    ↓
                   1NF
                    │
          Atomic values
          No repeating groups
                    │
                    ↓
                   2NF
                    │
          No partial dependency
                    │
                    ↓
                   3NF
                    │
          No transitive dependency
```

### ⭐ Final memory trick

```text
1NF → ATOMIC
      ↓
      One cell = One value

2NF → PARTIAL
      ↓
      Remove Partial Dependency

3NF → TRANSITIVE
      ↓
      Remove Transitive Dependency
```

**One-line answer to remember for interviews:**

> **1NF removes repeating groups, 2NF removes partial dependency, and 3NF removes transitive dependency.**
