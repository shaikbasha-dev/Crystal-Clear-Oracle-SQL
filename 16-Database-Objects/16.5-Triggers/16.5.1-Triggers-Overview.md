# 16.5.1-Triggers-Overview

## 1. What is a Trigger?

A **Trigger** is a prepared SQL statement that is **saved in the database** and is executed **automatically (autonomously)** when a particular event occurs. 

In simple words:

> **Stored Procedure → We call it explicitly**
> **Trigger → It gets activated automatically when its event happens**

---

## 2. Simple Example to Understand

Imagine a table called `table1`.

Suppose a new employee is inserted into `table1`.

We can create a Trigger that automatically inserts some information into `table2`.

```text
INSERT happens in table1
        ↓
Trigger detects the event
        ↓
Trigger automatically executes
        ↓
INSERT happens in table2
```

We don't separately call the Trigger.

---

## 3. Trigger and Stored Procedure

Triggers are described as a kind of Stored Procedure. 

| Stored Procedure         | Trigger                    |
| ------------------------ | -------------------------- |
| Stored in database       | Stored in database         |
| Called explicitly        | Called autonomously        |
| We explicitly execute it | Event causes it to execute |
| We provide the call      | Event activates it         |

### Easy memory:

```text
PROCEDURE → CALL
TRIGGER    → EVENT
```

---

# 4. Two Main Components of a Trigger

There are **two main components**:

1. **Event**
2. **Action**



### What is an Event?

An **event** is something that happens to a table.

Examples:

```text
INSERT
UPDATE
DELETE
```

### What is an Action?

An **action** is what the Trigger performs when the event occurs.

For example:

```text
Event:
INSERT into table1

Action:
INSERT corresponding data into table2
```

So:

```text
EVENT
  ↓
Something happens
  ↓
ACTION
  ↓
Trigger performs the specified SQL operation
```

---

# 5. Six Types of Events and Actions

There are six combinations listed:

| No. | Event / Action |
| --: | -------------- |
|   1 | Before Insert  |
|   2 | After Insert   |
|   3 | Before Update  |
|   4 | After Update   |
|   5 | Before Delete  |
|   6 | After Delete   |



The easiest way to remember them is:

```text
INSERT → BEFORE / AFTER
UPDATE → BEFORE / AFTER
DELETE → BEFORE / AFTER
```

---

# 6. Meaning of BEFORE and AFTER

### BEFORE

The Trigger executes **before** the specified event takes place.

```text
BEFORE INSERT
      ↓
Trigger action
      ↓
INSERT
```

### AFTER

The Trigger executes **after** the specified event takes place.

```text
INSERT
   ↓
AFTER INSERT
   ↓
Trigger action
```

The same idea applies to UPDATE and DELETE.

---

# 7. Trigger Syntax

### Question:

What is the general syntax for creating a Trigger?

### Answer / Syntax:

```sql
CREATE TRIGGER trigger_name
[BEFORE AFTER] [INSERT UPDATE DELETE]
ON table_name
FOR EACH ROW
BEGIN
    SQL Query;
END;
```



### Understanding the Syntax

| Part                       | Meaning                                   |
| -------------------------- | ----------------------------------------- |
| `CREATE TRIGGER`           | Creates a Trigger                         |
| `trigger_name`             | Name of the Trigger                       |
| `BEFORE / AFTER`           | Specifies when it executes                |
| `INSERT / UPDATE / DELETE` | Specifies the event                       |
| `ON table_name`            | Table on which the event occurs           |
| `FOR EACH ROW`             | Applies the Trigger for each affected row |
| `BEGIN`                    | Starts Trigger body                       |
| `SQL Query`                | Action performed by Trigger               |
| `END`                      | Ends Trigger                              |

---

# 8. Example of a Trigger

### Question:

Create a Trigger named `dec` that executes before an insert on `table1` and inserts the new `id` and `name` into `table2`.

### Answer / Query:

```sql
CREATE TRIGGER dec
BEFORE INSERT
ON table1
FOR EACH ROW
BEGIN
    INSERT INTO table2 VALUES(:NEW.id, :NEW.name);
END;
```

The example uses `:NEW` to refer to the values being inserted. 

> **Correction:** The source example has `before inser`; the correct keyword is `BEFORE INSERT`.

---

# 9. Understanding `:NEW` and `:OLD`

Triggers can use special references to access row values.

| Event  | Reference         |
| ------ | ----------------- |
| INSERT | `:NEW`            |
| UPDATE | `:NEW` and `:OLD` |
| DELETE | `:OLD`            |



### Easy memory:

```text
INSERT → NEW
UPDATE → OLD + NEW
DELETE → OLD
```

Why?

### INSERT

A new row is being created.

```text
:NEW
```

### UPDATE

An old value is changed to a new value.

```text
:OLD → :NEW
```

### DELETE

The existing row is being removed, so we refer to its old value.

```text
:OLD
```

---

# 10. Example Flow

Suppose:

```text
table1
---------
id   name
1    A
```

A new row is inserted.

### Question:

What happens when a new row is inserted into `table1` while the `dec` Trigger exists?

### Answer / Query:

```sql
INSERT INTO table1 VALUES(2, 'B');
```

The Trigger automatically responds to the `INSERT` event.

```text
INSERT INTO table1
        ↓
BEFORE INSERT Trigger
        ↓
:NEW.id   → 2
:NEW.name → B
        ↓
INSERT INTO table2
```

So the Trigger performs its defined action automatically.

---

# 11. Trigger vs Normal SQL Statement

| Normal SQL Statement               | Trigger                          |
| ---------------------------------- | -------------------------------- |
| We execute it ourselves            | Activated by an event            |
| Explicit execution                 | Autonomous execution             |
| Example: `INSERT`                  | Example: `BEFORE INSERT` Trigger |
| Executes when we issue the command | Executes when its event occurs   |

---

# 12. Trigger vs Stored Procedure — Most Important Difference

### Stored Procedure

```text
Create Procedure
       ↓
Stored in Database
       ↓
Call Procedure
       ↓
Execute
```

### Trigger

```text
Create Trigger
       ↓
Stored in Database
       ↓
Specified Event Occurs
       ↓
Trigger Executes Automatically
```

This distinction is one of the most important points to remember.

---

# 13. Important Points

* A Trigger is a **prepared SQL statement**.
* It is **saved in the database**.
* It is **called autonomously**.
* **Event** and **Action** are the two main components.
* The main events are **INSERT, UPDATE and DELETE**.
* Each can occur **BEFORE or AFTER**.
* Therefore, there are six combinations:

  * Before Insert
  * After Insert
  * Before Update
  * After Update
  * Before Delete
  * After Delete
* `:NEW` is associated with INSERT.
* UPDATE uses `:OLD` and `:NEW`.
* DELETE uses `:OLD`.
