# 16.3.1-Index-Overview

## 1. What is an Index?

An **Index** is a **data structure** used to speed up `SELECT` queries.

It helps Oracle **retrieve data faster from a table**. 

### Simple idea

Imagine a book 📖.

If you want to find a particular topic:

**Without an index:**

```text
Page 1 → Page 2 → Page 3 → Page 4 → ... → Required topic
```

You may have to search many pages.

**With an index:**

```text
Index
  ↓
Topic → Page Number
  ↓
Go directly to the required page
```

An SQL Index works with a similar basic idea: it helps Oracle locate required data more efficiently.

---

# 2. Why do we use an Index?

The main purpose is:

> **To speed up SELECT queries and retrieve data faster.**



For example, suppose an `emp` table contains a very large amount of employee data.

If we frequently search using:

```text
dept_id
```

an Index on `dept_id` can help with retrieving matching data faster.

---

# 3. What is an Index?

The important points are:

| Point        | Meaning                     |
| ------------ | --------------------------- |
| Index is a   | **Data structure**          |
| Main purpose | **Speed up SELECT queries** |
| Benefit      | **Faster data retrieval**   |
| Created on   | One or more table columns   |

The definition and purpose are stated directly in the Index section.

# 4. Simple Example

Suppose we have:

```text id="v5xq2m"
EMP TABLE
--------------------------------
EMP_ID | F_NAME | SALARY | DEPT_ID
--------------------------------
...
...
...
Thousands of rows
...
...
```

Now suppose we frequently search employees based on:

```text
DEPT_ID
```

We can create an Index on `dept_id`.

```text id="5o4yqv"
EMP TABLE
     │
     │
     └──────→ INDEX on DEPT_ID
                    │
                    ↓
             Faster retrieval
```

# 5. When is it Suitable to Create an Index?

There are **three situations** given:

### 1. When the data is very large

If a table contains a large amount of data, an Index can be useful.

```text
Small data  → Index may not be necessary
Large data  → Index can be useful
```

### 2. When a column is frequently used as a condition

For example, if we frequently use a column in a `WHERE` condition:

```sql id="f2x5kc"
SELECT *
FROM emp
WHERE dept_id = 22;
```

then that column can be a suitable candidate for an Index.

### 3. When the table is not updated frequently

If the table is not frequently updated, creating an Index can be suitable.

These three conditions are listed under when an Index is suitable. 

---

# 6. When is it NOT Suitable to Create an Index?

There are also three situations where creating an Index is not suitable.

### 1. When the data is very small

If the table contains very little data, an Index may not be necessary.

### 2. When the column is not frequently used as a condition

If a column is rarely used as a condition for retrieving data, creating an Index on it may not be suitable.

### 3. When the table is updated frequently

If a table is updated frequently, an Index may not be suitable.

These three situations are listed under when an Index is not suitable. 

---

# 7. Suitable vs Not Suitable

| Suitable to Create Index            | Not Suitable                            |
| ----------------------------------- | --------------------------------------- |
| Data is very large                  | Data is very small                      |
| Column frequently used as condition | Column not frequently used as condition |
| Table not updated frequently        | Table updated frequently                |

### Easy memory:

```text id="8ml2oc"
LARGE DATA
    +
FREQUENT CONDITION COLUMN
    +
LESS FREQUENT UPDATES
    ↓
INDEX IS SUITABLE
```

# 8. Example of an Index

### Question:

Create an Index named `dec` on the `dept_id` column of the `emp` table.

### Answer / Query:

```sql id="d2x9wq"
CREATE INDEX dec
ON emp(dept_id);
```



### Query Explanation

```text id="k0u8vz"
CREATE INDEX dec
```

Creates an Index named `dec`.

```text id="b6x4y7"
ON emp
```

Specifies that the Index belongs to the `emp` table.

```text id="v3x8nq"
(dept_id)
```

Specifies that the Index is created on the `dept_id` column.

### Flow

```text id="y6p7mc"
EMP TABLE
   │
   └── DEPT_ID
         ↓
    INDEX: DEC
         ↓
 Faster retrieval
```

# 9. Important Interview Questions

### Q1. What is an Index?

**Answer:**
An Index is a data structure used to speed up `SELECT` queries and retrieve data faster from a table.

### Q2. Why do we use an Index?

**Answer:**
We use an Index to improve the speed of data retrieval, especially when working with large amounts of data.

### Q3. When is an Index suitable?

**Answer:**

* When data is very large.
* When a column is frequently used as a condition.
* When the table is not updated frequently.

### Q4. When is an Index not suitable?

**Answer:**

* When data is very small.
* When the column is not frequently used as a condition.
* When the table is updated frequently.

### Q5. Give an example of creating an Index.

**Answer:**

```sql id="d9x3qt"
CREATE INDEX dec
ON emp(dept_id);
```
