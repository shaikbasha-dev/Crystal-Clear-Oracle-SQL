# 14.2.2.8-Drop-Constraint

## 1. What is DROP CONSTRAINT?

`DROP CONSTRAINT` is an operation of the `ALTER` command.

It is used to **remove an existing constraint from a table**.

For example, suppose we have a primary key constraint:

```text
BANK_DETAILS
      ↓
     b_pk
      ↓
PRIMARY KEY
      ↓
     BID
```

If we want to remove that constraint, we use `DROP CONSTRAINT`.

---

# 2. Why do we need DROP CONSTRAINT?

Sometimes a constraint that was added to a table is no longer required.

Instead of deleting the entire table, we can remove **only the constraint**.

```text
Existing Table
      ↓
DROP CONSTRAINT
      ↓
Constraint removed
      ↓
Table remains
```

The table itself is **not deleted**.

---

# 3. Syntax

### Question

**How do you drop an existing constraint from a table?**

### Syntax

```sql
ALTER TABLE table_name
DROP CONSTRAINT constraint_name;
```

### Syntax Explanation

| Part              | Meaning                              |
| ----------------- | ------------------------------------ |
| `ALTER`           | Used to modify an existing table     |
| `TABLE`           | Specifies the table                  |
| `table_name`      | Name of the table                    |
| `DROP CONSTRAINT` | Removes an existing constraint       |
| `constraint_name` | Name of the constraint to be removed |
| `;`               | Ends the SQL statement               |

---

# 4. Example

Suppose we previously added this constraint:


Now we want to remove it.

# 6. Why is the Constraint Name Important?

When adding a constraint, we give it a name.

For example:

### Question

**Add a primary key constraint named `b_pk` to `bid`.**

### Query

```sql
ALTER TABLE Bank_Details
ADD CONSTRAINT b_pk
PRIMARY KEY(bid);
```

Here:

```text
b_pk
```

is the **constraint name**.

Later, if we want to remove it, we use that same name.

### Question

**Remove the constraint named `b_pk`.**

### Query

```sql
ALTER TABLE Bank_Details
DROP CONSTRAINT b_pk;
```

So remember:

```text
ADD
 ↓
b_pk
 ↓
DROP
 ↓
b_pk
```

# 7. ADD CONSTRAINT vs DROP CONSTRAINT

| ADD CONSTRAINT                 | DROP CONSTRAINT                   |
| ------------------------------ | --------------------------------- |
| Adds a constraint              | Removes a constraint              |
| Uses `ADD CONSTRAINT`          | Uses `DROP CONSTRAINT`            |
| Requires constraint definition | Requires existing constraint name |
| Creates a rule                 | Removes a rule                    |

### Add Constraint

### Question

**Add a primary key constraint named `b_pk` on `bid`.**

### Query

```sql
ALTER TABLE Bank_Details
ADD CONSTRAINT b_pk
PRIMARY KEY(bid);
```

### Drop Constraint

### Question

**Remove the constraint named `b_pk`.**

### Query

```sql
ALTER TABLE Bank_Details
DROP CONSTRAINT b_pk;
```

---

# 8. DROP CONSTRAINT vs DROP TABLE

These are completely different.

| DROP CONSTRAINT           | DROP TABLE                     |
| ------------------------- | ------------------------------ |
| Removes only a constraint | Removes the table              |
| Table remains             | Table is removed               |
| Data remains in the table | Table and its data are removed |
| Uses `ALTER TABLE`        | Uses `DROP TABLE`              |

### Drop Constraint

### Question

**Remove the constraint `b_pk` from `Bank_Details`.**

### Query

```sql
ALTER TABLE Bank_Details
DROP CONSTRAINT b_pk;
```

The table remains.

### Drop Table

### Question

**Remove the `Bank_Details` table.**

### Query

```sql
DROP TABLE Bank_Details;
```

The table itself is removed.

# 9. Common Mistakes

### Mistake 1 — Forgetting `CONSTRAINT`

❌

```sql
ALTER TABLE Bank_Details
DROP b_pk;
```

✅

```sql
ALTER TABLE Bank_Details
DROP CONSTRAINT b_pk;
```

---

### Mistake 2 — Using the column name instead of the constraint name

Suppose:

```text
Column name     = BID
Constraint name = b_pk
```

To remove the constraint, we use:

```sql
ALTER TABLE Bank_Details
DROP CONSTRAINT b_pk;
```

**Not:**

```sql
ALTER TABLE Bank_Details
DROP CONSTRAINT bid;
```

The important thing is:

> `DROP CONSTRAINT` requires the **constraint name**.

---

# 10. Important Points

1. The table must already exist.
2. The constraint must already exist.
3. Use `ALTER TABLE`.
4. Use `DROP CONSTRAINT`.
5. Specify the **constraint name**.
6. Dropping a constraint does not drop the entire table.
7. The table continues to exist after the constraint is removed.
