# 16.3.2-When-to-Create-Index

An **Index** is suitable when it can help Oracle retrieve data faster. The three situations to remember are:

## 1. When the Data is Very Large

An Index is suitable when the table contains a **large amount of data**.

### Simple idea

```text
Small Table
   ↓
Less data to search

Large Table
   ↓
More data to search
   ↓
Index can help faster retrieval
```

The larger the amount of data, the more useful an Index can be for data retrieval. 

---

## 2. When a Column is Frequently Used as a Condition

An Index is suitable when a particular column is **frequently used as a condition** while retrieving data.

For example, suppose `dept_id` is frequently used in a condition:

### Question:

Retrieve employees whose department ID is 22.

### Query:

```sql id="j7q6n2"
SELECT *
FROM emp
WHERE dept_id = 22;
```

### Query Explanation:

```text
WHERE dept_id = 22
       ↑
Frequently used condition column
```

If `dept_id` is frequently used this way, creating an Index on `dept_id` can be suitable. 

---

## 3. When the Table is Not Updated Frequently

An Index is suitable when the table is **not updated frequently**.

Think:

```text
Table
 ↓
Mostly SELECT
 ↓
Few updates
 ↓
Index can be suitable
```

The condition given is that the table should **not be updated frequently**. 

---

# 4. All Three Conditions Together

Remember these three points:

| Condition                                | Index      |
| ---------------------------------------- | ---------- |
| Data is very large                       | ✅ Suitable |
| Column is frequently used as a condition | ✅ Suitable |
| Table is not updated frequently          | ✅ Suitable |

### Easy Memory Trick

```text id="8z2j6r"
       INDEX
         │
 ┌───────┼────────┐
 ↓       ↓        ↓
LARGE   WHERE    FEW
DATA    COLUMN   UPDATES
```

**L → W → F**

> **Large Data + Frequently used condition column + Few updates = Suitable for Index**

---

# 5. Interview Questions

### Q1. When is it suitable to create an Index?

**Answer:**

An Index is suitable:

1. When the data is very large.
2. When a column is frequently used as a condition.
3. When the table is not updated frequently.

### Q2. Should we create an Index on every column?

**Answer:**

No. The Index is particularly suitable when the column is frequently used as a condition, especially when the table contains large amounts of data.

### Q3. Is an Index suitable for a frequently updated table?

**Answer:**

The given rule is **no**—an Index is not suitable when the table is updated frequently. 

---

## 6. Interview-Ready Answer

> **An Index is suitable when the data is very large, a column is frequently used as a condition, and the table is not updated frequently.**
