# 16.1-Database-Objects-Overview

## 1. What is a Database Object?

A **Database Object** is something that is created and stored inside a database to perform a particular job.

For example:

* A **View** helps us see data through a virtual table.
* An **Index** helps retrieve data faster.
* A **Stored Procedure** stores SQL statements that can be reused.
* A **Trigger** performs an action automatically when an event occurs.
* A **Sequence** generates automatic numbers.
* A **Synonym** gives another name to a table.

These are the database objects covered here.  

---

## 2. Why do we need Database Objects?

Imagine an application has hundreds or thousands of tables and queries.

If we write everything again and again, it becomes difficult to manage.

Database objects help us perform common tasks more easily.

| Database Object      | Main Purpose                                               |
| -------------------- | ---------------------------------------------------------- |
| **View**             | Provides a virtual table and makes complex queries simpler |
| **Index**            | Helps retrieve data faster                                 |
| **Stored Procedure** | Stores SQL statements for reuse                            |
| **Trigger**          | Automatically performs an action when an event occurs      |
| **Sequence**         | Generates automatic numbers                                |
| **Synonym**          | Gives another name to a table                              |

# 4. View

### What is a View?

A **View** is a **virtual table** created on the basis of an original/actual table.

It does not represent a completely separate set of stored table data. It provides a way to work with the result of a query as a table.

### Why use a View?

A View can:

* Make a complex query simple.
* Provide data independence.



### Simple example

Suppose `emp` contains many columns:

```text
emp
--------------------------------
emp_id
f_name
salary
dept_id
email
phone
...
```

But we frequently need only:

```text
f_name
salary
dept_id
```

We can create a View containing those required columns.

### Question:

Create a view containing the employee first name, salary and department ID for employees whose department ID is 22.

### Query:

```sql
CREATE VIEW dec
AS
SELECT f_name, salary, dept_id
FROM emp
WHERE dept_id = 22;
```

### Query Explanation:

* `CREATE VIEW dec` → creates a View named `dec`.
* `SELECT f_name, salary, dept_id` → selects the required columns.
* `FROM emp` → takes the data from `emp`.
* `WHERE dept_id = 22` → selects employees belonging to department 22.

The View can then be queried like a table.

# 5. Index

### What is an Index?

An **Index** is a data structure used to **speed up SELECT queries** and help retrieve data faster from a table. 

### Simple analogy

Think about a book.

Without an index:

> You may have to search page by page.

With an index:

> You can quickly locate the required topic.

An SQL Index works similarly—it helps Oracle find required data faster.

### When is an Index suitable?

An Index is suitable:

* When the data is very large.
* When a column is frequently used as a condition.
* When the table is not updated frequently. 

### When is it not suitable?

* When the data is very small.
* When the column is not frequently used as a condition.
* When the table is updated frequently. 

### Question:

Create an index on the `dept_id` column of the `emp` table.

### Query:

```sql
CREATE INDEX dec
ON emp(dept_id);
```

### Query Explanation:

* `CREATE INDEX dec` → creates an Index named `dec`.
* `ON emp` → the Index belongs to the `emp` table.
* `(dept_id)` → the Index is created on `dept_id`.

# 6. Stored Procedure

### What is a Stored Procedure?

A **Stored Procedure** is a group of SQL statements stored in the database and reused whenever required.

It has to be **called explicitly**. 

### Simple analogy

Suppose you repeatedly perform the same task:

> Increase salary of employees belonging to a particular department.

Instead of writing the complete `UPDATE` query every time, we can store the operation inside a procedure and call it whenever required.

### Question:

Create a procedure that increases salary based on the supplied salary amount and department ID.

### Query:

```sql
CREATE PROCEDURE hike_sal(sal IN NUMBER, did IN NUMBER)
AS
BEGIN
    UPDATE emp1
    SET salary = salary + sal
    WHERE dept_id = did;
END;
```

### Query Explanation:

* `hike_sal` → procedure name.
* `sal` → salary amount to increase.
* `did` → department ID.
* `UPDATE emp1` → modifies employee salary.
* `salary = salary + sal` → increases salary.
* `WHERE dept_id = did` → applies the increase to the specified department.

### Important point

A Stored Procedure must be **called explicitly**.

# 7. Trigger

### What is a Trigger?

A **Trigger** is a type of stored procedure that is saved in the database and called **automatically** when a particular event occurs. 

### Simple analogy

Think about an automatic door.

```text
Person comes
     ↓
Sensor detects person
     ↓
Door opens automatically
```

You don't manually tell the door:

> "Open now."

The event causes the action automatically.

Similarly:

```text
SQL Event
    ↓
Trigger detects event
    ↓
Action happens automatically
```

### Main components

A Trigger has two important components:

1. **Event**
2. **Action**

When the specified event occurs, the corresponding action takes place. 

### Events/Actions covered

| Event         | Action                            |
| ------------- | --------------------------------- |
| Before Insert | Trigger executes before insertion |
| After Insert  | Trigger executes after insertion  |
| Before Update | Trigger executes before updating  |
| After Update  | Trigger executes after updating   |
| Before Delete | Trigger executes before deletion  |
| After Delete  | Trigger executes after deletion   |

# 8. Sequence

### What is a Sequence?

A **Sequence** generates automatic numbers for a specified column. 

For example:

```text
1
2
3
4
5
...
```

Instead of manually entering an ID every time, a Sequence can generate the numbers.

### Important keywords

| Keyword   | Purpose                  |
| --------- | ------------------------ |
| `NEXTVAL` | Generates the next value |
| `CURRVAL` | Gives the current value  |



### Question:

Create a Sequence starting from 1 and increase its value by 1.

### Query:

```sql
CREATE SEQUENCE Dec
START WITH 1
INCREMENT BY 1;
```

### Query Explanation:

* `CREATE SEQUENCE Dec` → creates a Sequence named `Dec`.
* `START WITH 1` → first value starts at 1.
* `INCREMENT BY 1` → each next value increases by 1.

---

# 9. Synonym

### What is a Synonym?

A **Synonym** is used to give **another name to a table**. 

### Simple example

Suppose the actual table is:

```text
emp
```

We can create another name:

```text
emp_details
```

Then we can use the synonym name when referring to the table.

### Question:

Create a synonym named `emp_details` for the `emp` table.

### Query:

```sql
CREATE SYNONYM emp_details
FOR emp;
```

### Query Explanation:

* `CREATE SYNONYM emp_details` → creates the synonym.
* `FOR emp` → tells Oracle that `emp_details` refers to the `emp` table.
