# 19.2-Database-Anomalies

When a database table is **poorly designed and contains repeated data**, three common problems can occur.

These problems are called **Database Anomalies**.

There are three major anomalies:

1. **Insert Anomaly**
2. **Update Anomaly**
3. **Delete Anomaly**

---

## 1. What is a Database Anomaly?

A **database anomaly** is an unwanted problem that occurs while **inserting, updating, or deleting data** because the table structure is not properly organized.

### Simple idea

Suppose we store this information in one table:

| Student_ID | Student_Name | Course_ID | Course_Name | Professor |
| ---------- | ------------ | --------- | ----------- | --------- |
| 101        | Ravi         | C01       | Java        | Kumar     |
| 102        | Anil         | C01       | Java        | Kumar     |
| 103        | Sara         | C02       | Python      | Priya     |

Notice that:

* `Java` is repeated.
* `Kumar` is repeated.
* If many students take the same course, the same course information is stored many times.

This repetition can create problems.

---

# 2. Insert Anomaly

## What is Insert Anomaly?

**Insert Anomaly** occurs when we **cannot insert some information into a table without having some unrelated information available**.

### Simple example

Suppose we want to add a new course:

> Course C03 = SQL
> Professor = Ahmed

But no student has enrolled in SQL yet.

Our table requires `Student_ID` and `Student_Name` for every row.

So we may be forced to do something like:

| Student_ID | Student_Name | Course_ID | Course_Name | Professor |
| ---------- | ------------ | --------- | ----------- | --------- |
| ?          | ?            | C03       | SQL         | Ahmed     |

We don't have student information.

Therefore, **course information cannot be stored independently**.

That is an **Insert Anomaly**.

### Easy memory

> **Want to INSERT something, but cannot insert it independently → Insert Anomaly**

---

# 3. Update Anomaly

## What is Update Anomaly?

**Update Anomaly** occurs when the same information is stored in multiple rows and we have to update it in multiple places.

Consider:

| Student_ID | Student_Name | Course_ID | Course_Name | Professor |
| ---------- | ------------ | --------- | ----------- | --------- |
| 101        | Ravi         | C01       | Java        | Kumar     |
| 102        | Anil         | C01       | Java        | Kumar     |
| 103        | Sara         | C02       | Python      | Priya     |

Suppose Professor **Kumar** changes his name to **Kumar Reddy**.

The information appears in multiple rows.

We must update:

```text
Row 1 → Kumar → Kumar Reddy
Row 2 → Kumar → Kumar Reddy
```

If we update only one row:

| Student_ID | Student_Name | Course_ID | Course_Name | Professor   |
| ---------- | ------------ | --------- | ----------- | ----------- |
| 101        | Ravi         | C01       | Java        | Kumar Reddy |
| 102        | Anil         | C01       | Java        | Kumar       |
| 103        | Sara         | C02       | Python      | Priya       |

Now the database contains **two different values for the same professor**.

This creates inconsistent data.

That is an **Update Anomaly**.

### Easy memory

> **Same information repeated → update it everywhere → risk of inconsistency → Update Anomaly**

---

# 4. Delete Anomaly

## What is Delete Anomaly?

**Delete Anomaly** occurs when deleting one piece of information **accidentally causes another important piece of information to be lost**.

Consider:

| Student_ID | Student_Name | Course_ID | Course_Name | Professor |
| ---------- | ------------ | --------- | ----------- | --------- |
| 101        | Ravi         | C01       | Java        | Kumar     |
| 102        | Anil         | C01       | Java        | Kumar     |
| 103        | Sara         | C02       | Python      | Priya     |

Suppose Sara leaves the college.

We delete Sara's row:

| Student_ID | Student_Name | Course_ID | Course_Name | Professor |
| ---------- | ------------ | --------- | ----------- | --------- |
| 101        | Ravi         | C01       | Java        | Kumar     |
| 102        | Anil         | C01       | Java        | Kumar     |

Now imagine Sara was the **only student enrolled in Python**.

By deleting Sara's record, we also lose:

```text
Course = Python
Professor = Priya
```

The course information disappears even though the course itself still exists.

That is a **Delete Anomaly**.

### Easy memory

> **DELETE one record → accidentally lose other important information → Delete Anomaly**

---

# 5. Three Anomalies — Simple Comparison

| Anomaly            | Problem occurs during | Main problem                                               |
| ------------------ | --------------------- | ---------------------------------------------------------- |
| **Insert Anomaly** | INSERT                | Cannot insert information independently                    |
| **Update Anomaly** | UPDATE                | Same information must be changed in multiple places        |
| **Delete Anomaly** | DELETE                | Deleting one record may remove other important information |

### One-line memory trick

```text
INSERT → Can't insert independently
UPDATE → Must update repeatedly
DELETE → Accidentally lose information
```

---

# 6. Why Do These Anomalies Occur?

The main reason is **poor database design and unnecessary data redundancy**.

In our table:

```text
Student + Course + Professor
```

are all stored together.

Because course and professor information is repeated for different students, problems can occur.

A properly normalized database separates the information into appropriate tables.

For example:

```text
STUDENT
   ↓
COURSE
   ↓
PROFESSOR
```

and relationships are maintained using keys.

Normalization helps us reduce these anomalies.

# 7. Interview Questions

### Q1. What is a database anomaly?

**Answer:**
A database anomaly is an unwanted problem that occurs during insertion, updating, or deletion of data due to improper database design.

---

### Q2. What are the three types of database anomalies?

**Answer:**

1. Insert Anomaly
2. Update Anomaly
3. Delete Anomaly

---

### Q3. What is Insert Anomaly?

**Answer:**
Insert Anomaly occurs when we cannot insert certain information into a table without having some unrelated information.

---

### Q4. What is Update Anomaly?

**Answer:**
Update Anomaly occurs when the same information is repeated in multiple rows and updating it in one place but not another causes inconsistent data.

---

### Q5. What is Delete Anomaly?

**Answer:**
Delete Anomaly occurs when deleting a record unintentionally removes other important information from the database.

---

### Q6. How can database anomalies be reduced?

**Answer:**
Database anomalies can be reduced by properly designing and **normalizing** the database.
