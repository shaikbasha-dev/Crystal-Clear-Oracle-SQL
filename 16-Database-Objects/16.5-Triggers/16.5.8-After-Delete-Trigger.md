# 16.5.8-After-Delete-Trigger

## 1. What is an AFTER DELETE Trigger?

An **AFTER DELETE Trigger** is a Trigger whose action is executed **after an existing row has been deleted from a table**.

Break the name into two parts:

```text
AFTER  → When?
DELETE → Which event?
```

So the flow is:

```text
DELETE happens
     ↓
Row is deleted
     ↓
AFTER DELETE Trigger executes
     ↓
Trigger Action
```

A Trigger is a prepared SQL statement saved in the database and called autonomously when its specified event occurs. 

---

## 2. Why is it called AFTER DELETE?

Because the **DELETE operation happens first**, and the Trigger action happens afterward.

```text
BEFORE DELETE

Trigger Action
      ↓
DELETE
```

Whereas:

```text
AFTER DELETE

DELETE
  ↓
Trigger Action
```

### Easy memory

> **BEFORE DELETE → Trigger first, DELETE next**
> **AFTER DELETE → DELETE first, Trigger next**

---

## 3. General Syntax

### Question:

What is the syntax for creating an AFTER DELETE Trigger?

### Answer / Syntax:

```sql
CREATE TRIGGER trigger_name
AFTER DELETE
ON table_name
FOR EACH ROW
BEGIN
    SQL Query;
END;
```

The Trigger syntax specifies the timing, event, table and SQL action. 

---

## 4. Understanding the Syntax

| Part             | Meaning                          |
| ---------------- | -------------------------------- |
| `CREATE TRIGGER` | Creates a Trigger                |
| `trigger_name`   | Name of the Trigger              |
| `AFTER`          | Action occurs after the event    |
| `DELETE`         | Event that activates the Trigger |
| `ON table_name`  | Table on which DELETE occurs     |
| `FOR EACH ROW`   | Applies to each affected row     |
| `BEGIN`          | Starts Trigger body              |
| `SQL Query`      | Action performed by Trigger      |
| `END`            | Ends Trigger                     |

---

# 5. What happens during DELETE?

Suppose an employee record is deleted.

```text
Employee record exists
        ↓
DELETE operation
        ↓
Employee record is deleted
        ↓
AFTER DELETE Trigger
        ↓
Trigger Action
```

The important point is:

> The row is deleted **before** the AFTER DELETE Trigger performs its action.

---

# 6. What is `:OLD` in DELETE?

For a DELETE event, the row being removed is an existing row.

Therefore:

```text
DELETE → :OLD
```

The Trigger row-reference mapping is:

| Event  | Reference       |
| ------ | --------------- |
| INSERT | `:NEW`          |
| UPDATE | `:OLD` + `:NEW` |
| DELETE | `:OLD`          |



### Example

Suppose the employee being deleted has:

```text
ID       = 101
NAME     = Basha
SALARY   = 25000
```

Before deletion, these values can be referred to as:

```text
:OLD.id
:OLD.name
:OLD.salary
```

So:

```text
:OLD → values of the row being deleted
```

# 8. Example of a DELETE Event

### Question:

Delete an employee whose `emp_id` is `101` from `emp1`.

### Answer / Query:

```sql
DELETE FROM emp1
WHERE emp_id = 101;
```

If an AFTER DELETE Trigger exists on `emp1`, the flow is:

```text
DELETE FROM emp1
WHERE emp_id = 101
        ↓
Employee 101 is deleted
        ↓
AFTER DELETE Trigger
        ↓
Trigger Action executes
```

### Answer:

```text

```

```text

```

```text

```

```text
AFTER DELETE

      ↓
Trigger action executes
```

# 10. BEFORE DELETE vs AFTER DELETE

| BEFORE DELETE                       | AFTER DELETE                       |
| ----------------------------------- | ---------------------------------- |
| Trigger action occurs before DELETE | Trigger action occurs after DELETE |
| Timing = BEFORE                     | Timing = AFTER                     |
| Event = DELETE                      | Event = DELETE                     |
| Uses `:OLD`                         | Uses `:OLD`                        |

### Visual memory

```text
BEFORE DELETE

BEFORE Trigger
      ↓
DELETE
```

```text
AFTER DELETE

DELETE
  ↓
AFTER Trigger
```

---

# 11. DELETE and Its Row Reference

### Question:

Which row reference is associated with a DELETE event?

### Answer:

```text
:OLD
```

Why?

Because DELETE removes an **existing row**.

```text
Existing Row
     ↓
   :OLD
     ↓
  DELETE
```

The mapping is:

```text
INSERT → :NEW
UPDATE → :OLD + :NEW
DELETE → :OLD
```



---

# 12. All Six Trigger Combinations

After completing the INSERT, UPDATE and DELETE Trigger types:

| Event  | BEFORE | AFTER |
| ------ | :----: | :---: |
| INSERT |    ✅   |   ✅   |
| UPDATE |    ✅   |   ✅   |
| DELETE |    ✅   |   ✅   |

Therefore:

```text
1. BEFORE INSERT
2. AFTER INSERT
3. BEFORE UPDATE
4. AFTER UPDATE
5. BEFORE DELETE
6. AFTER DELETE
```

These are the six combinations listed for Triggers. 

---

# 13. Important Points

* `AFTER DELETE` is one of the six Trigger combinations.
* `AFTER` specifies the timing.
* `DELETE` specifies the event.
* The DELETE operation happens first.
* The Trigger action executes afterward.
* DELETE uses `:OLD`.
* `:OLD` represents the existing row being deleted.
* A Trigger executes autonomously when its specified event occurs.
