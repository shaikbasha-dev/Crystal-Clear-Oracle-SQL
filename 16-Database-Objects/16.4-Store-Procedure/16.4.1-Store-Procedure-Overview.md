# 16.4.1-Store-Procedure-Overview

## 1. What is a Stored Procedure?

A **Stored Procedure** is a set of SQL statements that is **stored in the database** and can be **reused again and again whenever required**.

One important point:

> A Stored Procedure has to be **called explicitly**. 

### Simple idea

Suppose we have a task that we need to perform repeatedly.

Instead of writing the same SQL statements every time:

```text id="8r6q9x"
SQL Statements
      ↓
   Store them
      ↓
Stored Procedure
      ↓
Call whenever required
```

---

# 2. Why do we use a Stored Procedure?

The main reason is **reusability**.

If the same SQL operation is required many times, we can store it as a procedure and call it whenever required.

```text id="v7s5cy"
Write SQL once
     ↓
Store in database
     ↓
Reuse again and again
```

The Stored Procedure is therefore useful for storing SQL statements that need to be reused. 

---

# 3. Important Characteristics

### 1. It is stored in the database

The SQL statements are stored as a procedure in the database.

### 2. It can be reused

The procedure can be used again whenever required.

### 3. It must be called explicitly

Unlike a Trigger, a Stored Procedure does **not execute automatically** just because an event occurs.

It must be called.



---

# 4. Stored Procedure vs Trigger

This is an important interview distinction.

| Stored Procedure             | Trigger                                  |
| ---------------------------- | ---------------------------------------- |
| Stored in database           | Stored in database                       |
| SQL statements can be reused | SQL statements execute based on an event |
| **Called explicitly**        | **Called autonomously/automatically**    |
| Requires an explicit call    | Executes when its specified event occurs |

The distinction between explicit calling for procedures and autonomous execution for triggers is stated in the relevant sections.  

### Easy memory:

```text id="6a3y5d"
PROCEDURE
    ↓
You call it
    ↓
It executes

TRIGGER
    ↓
Event occurs
    ↓
It executes automatically
```

---

# 5. Basic Structure

A Stored Procedure has this general structure:

```text id="9r4d2m"
CREATE PROCEDURE
       ↓
Procedure Name
       ↓
Parameters
       ↓
AS
       ↓
BEGIN
       ↓
SQL Query
       ↓
END
```

---

# 6. Syntax

### Question:

What is the syntax for creating a Stored Procedure?

### Answer / Syntax:

```sql id="7qv3jh"
CREATE PROCEDURE procedure_name(parameters)
AS
BEGIN
    SQL Query;
END;
```



> The procedure name is written in place of `procedure_name`, and parameters can be supplied when required.

---

# 7. Example

The example uses a procedure named `hike_sal`.

### Question:

Create a Stored Procedure that increases the salary of employees belonging to a specified department by a specified amount.

### Answer / Query:

```sql id="l4h6x8"
CREATE PROCEDURE hike_sal(sal IN NUMBER, did IN NUMBER)
AS
BEGIN
    UPDATE emp1
    SET salary = salary + sal
    WHERE dept_id = did;
END;
```



---

# 8. Query Explanation

### `CREATE PROCEDURE`

```sql id="5d3x1w"
CREATE PROCEDURE hike_sal
```

Creates a Stored Procedure named:

```text id="z9f6rk"
hike_sal
```

---

### Parameters

```sql id="f6w2nq"
(sal IN NUMBER, did IN NUMBER)
```

There are two parameters:

| Parameter | Meaning                   |
| --------- | ------------------------- |
| `sal`     | Salary amount to be added |
| `did`     | Department ID             |

Both are declared as `NUMBER` and use `IN`.

---

### `AS`

```sql id="t2h9vy"
AS
```

Marks the beginning of the procedure definition.

---

### `BEGIN`

```sql id="y8x3pk"
BEGIN
```

Starts the executable part of the procedure.

---

### UPDATE statement

```sql id="4w7s9e"
UPDATE emp1
SET salary = salary + sal
WHERE dept_id = did;
```

This performs the actual operation:

```text id="p6q2ks"
Existing Salary
      +
    sal
      ↓
New Salary
```

And:

```text id="m8z4fc"
dept_id = did
```

determines which department's employees are affected.

---

### `END`

```sql id="j5t8qw"
END;
```

Marks the end of the procedure.

---

# 9. Calling a Stored Procedure

Creating the procedure does not mean that it executes immediately.

It has to be **called explicitly**. 

### Question:

How do you call the `hike_sal` procedure with `2000` as the salary increase and `22` as the department ID?

### Answer / Query:

```sql id="m1y7cq"
BEGIN
    hike_sal(2000, 22);
END;
```



### Meaning:

```text id="3x8p0k"
hike_sal(2000, 22)
       │     │
       │     └── Department ID
       └──────── Salary increase
```

So the procedure is called with:

```text
sal = 2000
did = 22
```

# 11. Stored Procedure vs Normal SQL Query

| Normal SQL Query                  | Stored Procedure          |
| --------------------------------- | ------------------------- |
| Written and executed directly     | SQL statements are stored |
| May need to be written repeatedly | Can be reused             |
| No procedure name                 | Has a procedure name      |
| Direct execution                  | Called explicitly         |

### Q1. What is a Stored Procedure?

**Answer:**

**Answer:**

**Answer:**
No. It has to be **called explicitly**.

### Q4. Why do we use Stored Procedures?

**Answer:**
To store SQL statements that can be reused again and again whenever required.

**Answer:**

```text id="1q2m8r"

Parameters

```

**Answer:**
