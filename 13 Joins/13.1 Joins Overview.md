# 13.1 Joins Overview

## 1. What is a Join?

A **JOIN** is used to combine data from **two or more tables**.

Think about it like this:

Suppose we have two tables:

### EMP table

| EMP_ID | F_NAME      | DEPT_ID |
| -----: | ----------- | ------: |
|      1 | Akash       |      22 |
|      2 | Prabhakaran |      23 |
|      3 | John        |      24 |

### DEPT table

| DEPT_ID | DEPT_NAME   |
| ------: | ----------- |
|      22 | Development |
|      23 | Testing     |
|      24 | HR          |

Both tables have one common column:

**DEPT_ID**

Using that common column, we can combine information from both tables.

For example:

| F_NAME      | DEPT_NAME   |
| ----------- | ----------- |
| Akash       | Development |
| Prabhakaran | Testing     |
| John        | HR          |

So:

> **JOIN = Combining data from multiple tables using a relationship between them.** 

---

# 2. Why do we need Joins?

Usually, database information is divided into different tables.

For example:

```text
EMP
 └── Employee information

DEPT
 └── Department information
```

Instead of storing everything in one huge table, related information is kept separately.

When we need information from both tables, we use a **JOIN**.

### Simple example

**Question:**
Display employee name along with their department name.

The employee name is in `EMP`.

The department name is in `DEPT`.

Therefore, we need a JOIN between the two tables using:

```text
EMP.DEPT_ID = DEPT.DEPT_ID
```

---

# 3. How does a Join work?

Imagine two tables:

### Table 1

|  A |  B |
| -: | -: |
|  1 |  2 |
|  3 |  4 |
|  5 |  6 |
|  7 |  8 |

### Table 2

|  B |  C |
| -: | -: |
|  2 |  1 |
|  8 |  1 |
|  9 |  1 |

The common column is `B`.

If we join using:

```text
Table1.B = Table2.B
```

the matching values are:

```text
2 = 2
8 = 8
```

Therefore, the matching result is:

|  A |  B |  B |  C |
| -: | -: | -: | -: |
|  1 |  2 |  2 |  1 |
|  7 |  8 |  8 |  1 |

This is the basic idea behind an **Inner Join**.

# 4. Types of Joins

There are **7 types** covered here:

```text
1. Inner Join
2. Equi Join
3. Natural Join
4. Outer Join
   ├── Left Outer Join
   ├── Right Outer Join
   └── Full Outer Join
5. Cross Join
6. Cartesian Join
7. Self Join
```



Let's understand the basic purpose of each.

---

## 5. Inner Join

### Meaning

An **Inner Join** returns **only matching records** from the tables.

```text
Table 1          Table 2
   │                │
   └──── MATCH ─────┘
          ↓
     Only matches
```

It joins tables based on a common column.

It is also called a **Simple Join**. 

### Basic syntax

```sql
SELECT *
FROM Table1
INNER JOIN Table2
ON Table1.B = Table2.B;
```

The important part is:

```sql
ON Table1.B = Table2.B
```

This tells Oracle **how the two tables are related**.

---

# 6. Equi Join

An **Equi Join** is essentially an Inner Join where the joining condition is written using the `=` operator in the `WHERE` clause.

### Basic syntax

```sql
SELECT *
FROM Table1, Table2
WHERE Table1.B = Table2.B;
```

The important part is:

```sql
WHERE Table1.B = Table2.B
```



---

# 7. Natural Join

A **Natural Join** automatically uses columns having the **same name** in both tables.

You don't write the joining condition.

### Syntax

```sql
SELECT *
FROM Table1
NATURAL JOIN Table2;
```

There is **no `ON` condition**.

The common column is also displayed only once in the result. 

---

# 8. Outer Join

Outer Join is used when we also want to retain **non-matching records**.

There are three types:

```text
Left Outer Join
Right Outer Join
Full Outer Join
```

### Left Outer Join

Returns:

> **All rows from the left table + matching rows from the right table.**

### Right Outer Join

Returns:

> **All rows from the right table + matching rows from the left table.**

### Full Outer Join

Returns:

> **Matching and non-matching rows from both tables.**

These three forms are part of Outer Join. 

---

# 9. Cross Join

A **Cross Join** combines **every row of the first table with every row of the second table**.

For example:

```text
Table 1 → 4 rows
Table 2 → 3 rows
```

Result:

```text
4 × 3 = 12 rows
```

So every row from Table 1 is matched with every row from Table 2.



---

# 10. Cartesian Join

Cartesian Join also produces the **Cartesian product**.

### Syntax

```sql
SELECT *
FROM Table1, Table2;
```

If Table 1 has 4 rows and Table 2 has 3 rows:

```text
4 × 3 = 12 rows
```



So in this context:

```text
CROSS JOIN ≈ CARTESIAN JOIN
```

---

# 11. Self Join

A **Self Join** means joining a table **with itself**.

It may sound strange, but the idea is simple:

```text
EMP
 │
 ├── Copy 1
 │
 └── Copy 2
```

Oracle treats the same table as two copies during the query.

It is useful when we need to compare data within the **same table**. 

For example, comparing the salary of one employee with the salary of other employees.

---

# 12. Quick Comparison

| Join                 | Main Idea                              |
| -------------------- | -------------------------------------- |
| **Inner Join**       | Only matching records                  |
| **Equi Join**        | Inner join using `=` in `WHERE`        |
| **Natural Join**     | Automatically joins same-named columns |
| **Left Outer Join**  | All left + matching right              |
| **Right Outer Join** | All right + matching left              |
| **Full Outer Join**  | All matching + non-matching from both  |
| **Cross Join**       | Every row × every row                  |
| **Cartesian Join**   | Cartesian product                      |
| **Self Join**        | Table joined with itself               |

---

# 13. Most Important Idea

If you remember only one thing:

```text
                 JOINS
                   │
          Combine multiple tables
                   │
        ┌──────────┴──────────┐
        │                     │
   Matching data        Non-matching data
        │                     │
   Inner / Equi /       Outer Joins
   Natural
```

And:

```text
Cross / Cartesian → Everything with everything

Self Join → Table with itself
```

# 14. Interview Questions

### Question 1

**Why are Joins used in SQL?**

**Answer:**
Joins are used to combine data from two or more tables using related/common columns.

### Question 2

**Which Join returns only matching records?**

**Answer:**
Inner Join.

### Question 3

**Which Join returns all records from the left table?**

**Answer:**
Left Outer Join.

### Question 4

**Which Join returns all records from the right table?**

**Answer:**
Right Outer Join.

### Question 5

**Which Join returns records from both tables, including non-matching records?**

**Answer:**
Full Outer Join.

### Question 6

**Which Join joins a table with itself?**

**Answer:**
Self Join.

### Question 7

**Which Join produces a Cartesian product?**

**Answer:**
Cross Join / Cartesian Join.

### Question 8

**What is another name for Inner Join?**

**Answer:**
Simple Join.
