# 16.5.10-Deleting-a-Trigger

## 1. What does Deleting a Trigger mean?

Deleting a Trigger means **removing an existing Trigger from the database**.

The command used is:

```text id="2x7m1p"
DROP TRIGGER
```

The Trigger is removed from the database after the command is executed.

---

## 2. Syntax

### Question:

What is the syntax for deleting a Trigger?

### Answer / Syntax:

```sql
DROP TRIGGER trigger_name;
```



### Understanding the syntax

| Part           | Meaning                                |
| -------------- | -------------------------------------- |
| `DROP`         | Removes a database object              |
| `TRIGGER`      | Specifies that the object is a Trigger |
| `trigger_name` | Name of the Trigger to be deleted      |
| `;`            | Ends the SQL statement                 |

# 4. Complete Trigger Lifecycle

A Trigger can be understood through three stages:

```text
CREATE
   ↓
Trigger is created
   ↓
EVENT OCCURS
   ↓
Trigger executes automatically
   ↓
DROP
   ↓
Trigger is removed
```

### Create

### Question:

Create a Trigger named `dec`.

### Answer / Query:

```sql
CREATE TRIGGER dec
BEFORE INSERT
ON table1
FOR EACH ROW
BEGIN
    INSERT INTO table2 VALUES(:NEW.id, :NEW.name);
END;
```

### Execute automatically

### Question:

What happens when an INSERT occurs on `table1` while the `dec` Trigger exists?

### Answer / Query:

```sql
INSERT INTO table1 VALUES(1, 'A');
```

The `BEFORE INSERT` Trigger responds automatically.

### Delete

### Question:

Delete the Trigger named `dec`.

### Answer / Query:

```sql
DROP TRIGGER dec;
```

# 5. What Happens After Deleting the Trigger?

Before deleting:

```text id="8m2q7v"

   ↓
Trigger: dec
   ↓
INSERT event occurs
   ↓
Trigger executes
```

After:

### Question:

What command removes the `dec` Trigger?

### Answer / Query:

```sql
DROP TRIGGER dec;
```

After deletion:

```text id="7v4n2x"
Database
   ↓
Trigger: dec ❌
```

The Trigger no longer exists.

Therefore, an INSERT event will no longer activate that Trigger.

# 6. DROP TRIGGER vs DROP PROCEDURE

Both commands remove database objects, but they remove different objects.

| `DROP TRIGGER`               | `DROP PROCEDURE`                    |
| ---------------------------- | ----------------------------------- |
| Deletes a Trigger            | Deletes a Stored Procedure          |
| `DROP TRIGGER trigger_name;` | `DROP PROCEDURE procedure_name;`    |
| Example: `DROP TRIGGER dec;` | Example: `DROP PROCEDURE hike_sal;` |

### Easy memory

```text
TRIGGER
   ↓
DROP TRIGGER

PROCEDURE
   ↓
DROP PROCEDURE
```

---

# 7. DROP TRIGGER vs CREATE TRIGGER

| Create                    | Delete             |
| ------------------------- | ------------------ |
| `CREATE TRIGGER`          | `DROP TRIGGER`     |
| Creates Trigger           | Removes Trigger    |
| Trigger becomes available | Trigger is removed |

### Remember:

```text
CREATE → Create
DROP   → Delete
```

---

# 8. Important Points

* `DROP TRIGGER` is used to delete a Trigger.
* The Trigger name must be specified.
* Example:

```sql
DROP TRIGGER dec;
```

* Once the Trigger is deleted, it is no longer available to respond to its event.
* `DROP TRIGGER` is different from `DROP PROCEDURE`.

The syntax and example for deleting a Trigger are explicitly given as `DROP TRIGGER trigger_name;` and `DROP TRIGGER dec;`.
