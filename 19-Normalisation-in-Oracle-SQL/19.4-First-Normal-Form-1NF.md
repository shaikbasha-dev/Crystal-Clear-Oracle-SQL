# 19.4-First-Normal-Form-1NF

## 1. What is 1NF?

**1NF (First Normal Form)** is the first level of database normalization.

A table is in **1NF** when:

1. Each column contains **atomic (single) values**.
2. There are **no repeating groups** or multiple values in a single cell.
3. Each row represents a separate record.
4. Each column represents one type of information.

### Simple definition

> **1NF means: One cell → One value.**

---

# 2. Why Do We Need 1NF?

Consider this table:

| Student_ID | Student_Name | Phone_Numbers          |
| ---------- | ------------ | ---------------------- |
| 101        | Ravi         | 9876543210, 9123456780 |
| 102        | Anil         | 9988776655             |
| 103        | Sara         | 9000011111, 9000022222 |

The `Phone_Numbers` column contains **multiple values in one cell**.

For example:

```text
9876543210, 9123456780
```

This violates the atomic-value rule.

Therefore, this table is **not in 1NF**.

---

# 3. What Does Atomic Value Mean?

**Atomic value** means a value that cannot be meaningfully divided into multiple values for that column.

For example:

| Student_ID | Student_Name | Phone      |
| ---------- | ------------ | ---------- |
| 101        | Ravi         | 9876543210 |
| 102        | Anil         | 9988776655 |

Each `Phone` cell contains one phone number.

So the values are atomic.

### Memory trick

> **Atomic = Single value in one cell.**

---

# 4. Repeating Groups

Another common violation of 1NF is a **repeating group**.

For example:

| Student_ID | Student_Name | Phone1     | Phone2     | Phone3     |
| ---------- | ------------ | ---------- | ---------- | ---------- |
| 101        | Ravi         | 9876543210 | 9123456780 | 9000012345 |
| 102        | Anil         | 9988776655 | NULL       | NULL       |

Here we have:

```text
Phone1
Phone2
Phone3
```

This is a repeating group.

Instead of creating multiple phone columns, we should store phone numbers as separate rows.

---

# 5. Converting a Table into 1NF

### Before 1NF

| Student_ID | Student_Name | Phone_Numbers          |
| ---------- | ------------ | ---------------------- |
| 101        | Ravi         | 9876543210, 9123456780 |
| 102        | Anil         | 9988776655             |

The first row contains two phone numbers in one cell.

### After 1NF

| Student_ID | Student_Name | Phone      |
| ---------- | ------------ | ---------- |
| 101        | Ravi         | 9876543210 |
| 101        | Ravi         | 9123456780 |
| 102        | Anil         | 9988776655 |

Now:

```text
One cell → One value
```

Therefore, the data satisfies the **atomic-value requirement of 1NF**.

---

# 6. SQL Example

## Question

Create a student table where each student's phone number is stored as a separate atomic value.

### Answer / Query

```sql
CREATE TABLE Student_Phone
(
    Student_ID   NUMBER,
    Student_Name VARCHAR2(30),
    Phone        VARCHAR2(15)
);
```

Here:

* `Student_ID` stores the student ID.
* `Student_Name` stores the student name.
* `Phone` stores **one phone number per row**.

---

## Question

Insert Ravi's two phone numbers into the 1NF table.

### Answer / Query

```sql
INSERT INTO Student_Phone
VALUES (101, 'Ravi', '9876543210');

INSERT INTO Student_Phone
VALUES (101, 'Ravi', '9123456780');
```

Now the table contains:

| Student_ID | Student_Name | Phone      |
| ---------: | ------------ | ---------- |
|        101 | Ravi         | 9876543210 |
|        101 | Ravi         | 9123456780 |

Each cell contains a single value.

---

# 7. How to Identify Whether a Table is in 1NF?

Ask these questions:

### Question 1

> Does every cell contain only one value?

If **No** → Not 1NF.

### Question 2

> Are multiple values stored together in one cell?

If **Yes** → Not 1NF.

### Question 3

> Are there repeating columns such as Phone1, Phone2, Phone3?

If **Yes** → The design should be reconsidered for 1NF.

### Question 4

> Does each row represent one record?

If **Yes**, that supports the 1NF structure.

---

# 8. Important Example

Consider:

| Student_ID | Name | Courses      |
| ---------- | ---- | ------------ |
| 101        | Ravi | Java, Python |
| 102        | Anil | SQL          |
| 103        | Sara | Java, SQL    |

### Is this in 1NF?

**No.**

Why?

Because:

```text
Java, Python
```

are two values stored in one cell.

---

## Question

Convert the above data into an atomic structure.

### Answer

| Student_ID | Name | Course |
| ---------- | ---- | ------ |
| 101        | Ravi | Java   |
| 101        | Ravi | Python |
| 102        | Anil | SQL    |
| 103        | Sara | Java   |
| 103        | Sara | SQL    |

Now every `Course` cell contains only one value.

---

# 9. 1NF and Primary Key

A properly designed 1NF table should also have a way to uniquely identify each record.

Consider:

| Student_ID | Course |
| ---------- | ------ |
| 101        | Java   |
| 101        | Python |
| 102        | SQL    |

Here `Student_ID` alone is not unique because `101` appears twice.

The combination:

```text
(Student_ID, Course)
```

can identify each student-course record, assuming a student cannot take the same course more than once.

This is an example of a **composite key**.

This connects 1NF with the previous topic on keys.

---

# 10. What 1NF Does NOT Solve

This is very important.

Putting a table into 1NF **does not automatically remove every normalization problem**.

For example:

| Student_ID | Course_ID | Student_Name | Course_Name | Marks |
| ---------- | --------- | ------------ | ----------- | ----: |
| 101        | C01       | Ravi         | Java        |    80 |
| 101        | C02       | Ravi         | Python      |    90 |

All cells contain single values.

So the table can satisfy the **1NF atomicity requirement**.

But there can still be **partial dependencies**:

```text
Student_ID → Student_Name
Course_ID → Course_Name
```

Those are issues addressed when learning **2NF**.

### Therefore:

```text
1NF
 ↓
Remove repeating groups / multi-valued cells
 ↓
Atomic values
 ↓
2NF
 ↓
Deal with partial dependency
```

---

# 11. 1NF vs Not 1NF

| Not in 1NF                               | In 1NF                                |
| ---------------------------------------- | ------------------------------------- |
| Multiple values in one cell              | One value per cell                    |
| Repeating groups                         | No repeating groups                   |
| `Java, Python` in one cell               | `Java` and `Python` in separate rows  |
| Difficult to work with individual values | Easier to work with individual values |

---

# 12. Common Confusion

### ❌ Wrong idea

> "If every column has a value, the table is in 1NF."

Not necessarily.

The important point is **atomicity**, not merely whether cells are empty or filled.

---

### ❌ Wrong idea

> "A table can never have NULL in 1NF."

Incorrect.

A NULL value by itself does not mean that the table violates 1NF.

The main concern here is that a cell should not contain a **set/list of multiple values**.

---

### ❌ Wrong idea

> "1NF removes all redundancy."

No.

1NF primarily deals with **atomic values and repeating groups**.

Further normalization handles other dependency and redundancy problems.

---

# 13. Interview Questions

### Q1. What is 1NF?

**Answer:**
1NF, or First Normal Form, requires a table to contain atomic values and avoid repeating groups or multiple values in a single cell.

### Q2. What is an atomic value?

**Answer:**
An atomic value is a single value stored in a cell.

### Q3. What is the main rule of 1NF?

**Answer:**

> **One cell should contain one value.**

### Q4. What is a repeating group?

**Answer:**
A repeating group occurs when the same type of attribute is repeated across multiple columns or when multiple values of the same attribute are stored together.

### Q5. Does 1NF remove all redundancy?

**Answer:**
No. 1NF mainly addresses atomicity and repeating groups. Other normalization levels address additional redundancy and dependency problems.

### Q6. Which normal form comes after 1NF?

**Answer:**
**2NF — Second Normal Form.**

---

# 14. Interview-Ready Answer

> **First Normal Form (1NF) is the first level of normalization. A table is in 1NF when each cell contains a single atomic value and there are no repeating groups or multiple values stored in one cell. 1NF helps organize data into a proper tabular structure, but it does not by itself eliminate all redundancy or dependency problems.**
