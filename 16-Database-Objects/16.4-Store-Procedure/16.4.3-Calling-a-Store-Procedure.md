# 16.4.3-Calling-a-Store-Procedure

## 1. What does Calling a Stored Procedure mean?

Calling a Stored Procedure means **executing a procedure that has already been created and stored in the database**.

Remember:

```text
CREATE PROCEDURE
       ↓
Procedure is created and stored
       ↓
CALL PROCEDURE
       ↓
SQL statements inside it execute
```

A Stored Procedure has to be **called explicitly**. 

---

# 2. Syntax

### Question:

What is the syntax for calling a Stored Procedure?

### Answer / Syntax:

```sql id="x3v7m1"
BEGIN
    procedure_name(procedure_values);
END;
```



### Syntax Explanation

| Part               | Meaning                          |
| ------------------ | -------------------------------- |
| `BEGIN`            | Starts the execution block       |
| `procedure_name`   | Name of the procedure to call    |
| `procedure_values` | Values supplied to the procedure |
| `END`              | Ends the execution block         |

---

# 3. Procedure Being Called

The procedure created earlier is:

### Question:

What procedure is being called?

### Answer / Procedure:

```sql id="m5r8q2"
CREATE PROCEDURE hike_sal(sal IN NUMBER, did IN NUMBER)
AS
BEGIN
    UPDATE emp1
    SET salary = salary + sal
    WHERE dept_id = did;
END;
```

This procedure accepts two values:

```text id="z4c7n9"
sal → salary increase
did → department ID
```

---

# 4. Calling the Procedure

### Question:

Call the `hike_sal` procedure by passing `2000` as the salary increase and `22` as the department ID.

### Answer / Query:

```sql id="k8p2w6"
BEGIN
    hike_sal(2000, 22);
END;
```



---

# 5. Query Explanation

Let's understand:

```sql id="v6t3q1"
hike_sal(2000, 22);
```

The procedure has two parameters:

```sql id="q1x5m7"
hike_sal(sal, did)
```

We provide:

```text id="n4c8y2"
2000 → sal
 22  → did
```

So Oracle executes the procedure as if the values are:

```text id="r7m3k9"
sal = 2000
did = 22
```

---

# 6. What happens inside the Procedure?

The procedure contains:

```sql id="f8w2p4"
UPDATE emp1
SET salary = salary + sal
WHERE dept_id = did;
```

After calling:

```sql id="g5k9x1"
hike_sal(2000, 22);
```

the values become:

```text id="s2v7n6"
sal = 2000
did = 22
```

Therefore, logically:

```text id="c4m8q3"
EMP1
  ↓
Find employees where dept_id = 22
  ↓
Increase their salary by 2000
```

---

# 7. Complete Flow

```text id="p9x4k7"
CREATE PROCEDURE
       ↓
    hike_sal
       ↓
Stored in Database
       ↓
BEGIN
       ↓
hike_sal(2000, 22)
       ↓
Procedure executes
       ↓
Salary is increased for dept_id = 22
```

# 8. Creating vs Calling a Procedure

| Creating                                               | Calling                      |
| ------------------------------------------------------ | ---------------------------- |
| Creates the procedure                                  | Executes the procedure       |
| Uses `CREATE PROCEDURE`                                | Uses `BEGIN ... END`         |
| Procedure gets stored                                  | Stored procedure is executed |
| Does not perform the procedure's operation immediately | Performs the operation       |

### Creating:

### Question:

Create the salary hike procedure.

### Query:

```sql id="c7v2m5"
CREATE PROCEDURE hike_sal(sal IN NUMBER, did IN NUMBER)
AS
BEGIN
    UPDATE emp1
    SET salary = salary + sal
    WHERE dept_id = did;
END;
```

### Calling:

### Question:

Call the procedure for a salary increase of `2000` for department `22`.

### Query:

```sql id="u6p3z8"
BEGIN
    hike_sal(2000, 22);
END;
```

# 9. Why is Explicit Calling Important?

A Stored Procedure does **not execute simply because it exists**.

```text id="e3q8m6"
Procedure created
       ↓
Stored in database
       ↓
Nothing happens until it is called
       ↓
Procedure called
       ↓
SQL statements execute
```

This is the major point to remember about calling a Stored Procedure. 

---

# 10. Stored Procedure vs Trigger

This is very important for interviews.

```text id="w8n4c2"
STORED PROCEDURE
      ↓
Called explicitly

TRIGGER
      ↓
Called autonomously
when specified event occurs
```

The Stored Procedure section states that it must be called explicitly, while the Trigger section describes triggers as being called autonomously.

# 11. Interview Questions

### Q1. How do you call a Stored Procedure?

**Answer:**

```sql id="k5y8r3"
BEGIN
    procedure_name(procedure_values);
END;
```

### Q2. How do you call `hike_sal`?

**Answer:**

```sql id="r4m7x2"
BEGIN
    hike_sal(2000, 22);
END;
```

### Q3. What does `2000` represent?

**Answer:**
It represents the value supplied to the `sal` parameter.

### Q4. What does `22` represent?

**Answer:**
It represents the value supplied to the `did` parameter.

### Q5. Does a Stored Procedure execute automatically?

**Answer:**
No. It must be **called explicitly**.

### Q6. What happens when `hike_sal(2000,22)` is called?

**Answer:**
The procedure updates `emp1` and increases the salary by `2000` for employees whose department ID is `22`.
